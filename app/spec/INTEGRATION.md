# Контракт стыковки экранов

Экраны пишут разные исполнители, а навигация одна и живёт в `Sources/App/`,
куда писателям экранов ходить нельзя. Чтобы стыковка не требовала правок в
чужой папке, имена и подписи корневых вью фиксируются заранее — здесь.

## Правило

1. Ядро (`Core`/`App`) объявляет маршруты и фабрику, которая по маршруту отдаёт вью.
   Пока экран не написан, фабрика возвращает заглушку с именем `…ScreenStub`.
2. Писатель экрана создаёт в своей папке `Sources/Features/<Имя>/` структуру
   РОВНО с именем из таблицы и ровно с такими параметрами инициализации.
3. Оркестратор при приёмке меняет в фабрике одну строку: заглушку на настоящий экран.
   Писатель фабрику не трогает.

| ---------------- | ------------------------ | --------------------- | ------------------------------- |
| Сегодня          | `/today`                 | `TodayScreen`         | —                               |

| Лента дня        | `/timeline`              | `TimelineScreen`      | —                               |
| Чат              | `/chat`                  | `ChatScreen`          | —                               |
| Карточка задачи  | `/task/:id`              | `TaskDetailScreen`    | `taskID: String`                |
| Создание задачи  | `/task/new`              | `TaskFormScreen`      | `taskID: String?` (nil — новая), `presetDueToday: Bool = false`, `startDictation: Bool = false` |
| Заметки          | `/notes`                 | `NotesScreen`         | —                               |

Два дополнительных параметра формы задачи — не украшение: в вебе меню создания
открывает форму ссылками вида `/task/new?due=today` и `/task/new?dictate=1`
(«задача на сегодня» и «надиктовать»). Без них эти пункты меню теряют смысл,
поэтому у формы они есть со значениями по умолчанию.

Маршрута `/inbox` в приложении нет — экран убран из веба 26.08.2026, нативный
аналог не делаем.

## Что экран может ждать от ядра

- Сторы и модели из `Core` — только чтение чужого кода, правки просить у оркестратора.
- Тему, метрики и готовые кирпичи из `DesignSystem` (строка задачи, бейджи, шапка,
  пустое состояние, поля, кнопки, шторка).
- Переход на другой экран — через маршрут из таблицы, а не через прямое создание вью
  соседней функции: иначе экраны сцепятся между собой и их нельзя будет сдавать по одному.
