# TaskFlow — спецификация экранов, часть 1

Документ описывает поведение и состав первой половины экранов TaskFlow по факту
кода на 31.08.2026 (React + Vite, `~/Проекты/New-Todoist/src`). Цель — дать
Swift-разработчику возможность воспроизвести экраны в SwiftUI один-в-один, не
читая исходники React.

**Разобранные файлы:** `App.tsx`, `components/Layout.tsx`, `components/UI.tsx`,
`components/AnimatedTabBar.tsx`, `components/FanMenu.tsx`, `components/CreateMenu.tsx`,
`screens/TodayScreen.tsx`, `screens/UpcomingScreen.tsx`, `screens/OverviewScreen.tsx`,
`screens/InboxScreen.tsx`, `screens/TaskDetailScreen.tsx`, `screens/TaskFormScreen.tsx`,
`components/TaskRow.tsx`, `components/TaskBoard.tsx`, `components/DayHours.tsx`,
`components/UpcomingCalendar.tsx`, `components/RescheduleSheet.tsx`,
`components/TaskFilterSheet.tsx`, плюс для точности форматов и персистентности —
`components/TaskFields.tsx`, `lib/date.ts`, `lib/priority.ts`, `lib/taskFilters.ts`,
`components/PlannerProjectChips.tsx`, `store/index.ts`.

**⚠️ Две вещи, где живой код разошёлся с тем, как экраны названы в задании:**

1. **Экран «Входящие» (`InboxScreen.tsx`) не подключён к роутингу.** Маршрута
   `/inbox` в `App.tsx` нет, компонент нигде не импортируется. Раздел удалён из
   продукта 26.08.2026 (заменён «Обзором» как стартовым экраном и «Проектами»),
   файл остался в дереве как образец кода, но недостижим из UI. Описан в разделе 6
   как справочный, воспроизводить как живой экран не нужно.
2. **«Веер-меню» (FanMenu) сейчас НЕ активен.** В коде это полноценный компонент
   (`components/FanMenu.tsx`), но `Layout.tsx` жёстко выбирает вариант нижней
   навигации константой `MOBILE_NAV_STYLE: "fan" | "tabbar" = "tabbar"` — сейчас
   стоит `"tabbar"`. Реально работает связка **BottomNav (плоский таб-бар) +
   AnimatedTabBar + CreateMenu** (плоское меню «что создать», раскрывающееся вверх
   от центральной кнопки). FanMenu описан в разделе 2.2 как то, что есть в коде и
   включается одной константой, но НЕ то, что видит пользователь сегодня.

## 1. Оболочка приложения

### 1.1 Маршруты (`App.tsx`)

Все маршруты обёрнуты в `<Route element={<Layout />}>` — общая рамка (шапка/навигация)
одна на приложение, экраны рендерятся в `<Outlet/>`.

| Путь                                                                                                                                                        | Экран               | Примечание                                     |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- | ---------------------------------------------- |
| `/`                                                                                                                                                         | —                   | редирект на `/overview`                        |
| `/today`                                                                                                                                                    | TodayScreen         | «Сегодня»                                      |
| `/timeline`                                                                                                                                                 | TodayScreenTimeline | не входит в эту часть спеки                    |
| `/inbox-timeline`                                                                                                                                           | InboxScreenTimeline | не входит в эту часть спеки                    |
| `/upcoming`                                                                                                                                                 | UpcomingScreen      | «Планирование»                                 |
| `/overview`                                                                                                                                                 | OverviewScreen      | «Обзор», стартовый экран                       |
| `/settings`, `/settings/voice-models`, `/settings/integrations`, `/settings/templates`                                                                      | —                   | вне этой части                                 |
| `/task/:id`                                                                                                                                                 | TaskDetailScreen    | карточка задачи (read-only + отметка подзадач) |
| `/task/new`, `/task/:id/edit`                                                                                                                               | TaskFormScreen      | одна форма на создание и правку                |
| `/notifications`, `/chat`, `/activity`, `/agents`, `/agent-work`, `/projects`, `/projects/:id`, `/labels`, `/labels/:id`, `/search`, `/notes`, `/notes/:id` | —                   | вне этой части                                 |

`/inbox` **отсутствует** — см. предупреждение выше и раздел 6.

**NotFoundScreen** (любой нераспознанный путь) — дословно:

- Заголовок: «**Страница не найдена**»
- Текст: «**Такого адреса нет в приложении. Возможно, ссылка устарела.**»
- Кнопка: «**На главную**» → `/`

### 1.2 Deep links (`taskflow://...`)

| Ссылка                                                        | Переход                        |
| ------------------------------------------------------------- | ------------------------------ |
| `taskflow://dictate`, `taskflow://new-task`, `taskflow://new` | `/task/new?dictate=1`          |
| `taskflow://task/:id`                                         | `/task/:id`                    |
| `taskflow://inbox`, `taskflow://overview`                     | `/overview`                    |
| `taskflow://today`                                            | `/today`                       |
| что-то ещё / нераспознано                                     | `/task/new?dictate=1` (дефолт) |

Своя экранная клавиатура (`AppKeyboard.tsx`) в коде есть, но **отключена** с
20.08.2026 — используется системная клавиатура iOS.

### 1.3 `Layout.tsx` — общая рамка экрана

Мобильная ветка (`isMobile`):

```
<div class="h-[100dvh] overflow-hidden flex flex-col">
  [скроллер с pull-to-refresh]
    <Outlet/>   ← сам экран
  [BottomNav или FanMenu, если не hideNav]
  [FAB, если не hideFAB]
</div>
```

- **Pull-to-refresh**: индикатор — стрелка вниз, доворачивается на 180°, когда жест
  «взведён» (armed), при отпускании — спиннер на время обновления запроса.
- **Панель навигации показывается на КАЖДОМ экране** (решение от 27.08.2026), кроме
  `/chat` — там своя строка ввода вместо панели. `hideNav === true` только на `/chat`.
- **FAB** (круглая кнопка «+») скрыта (`hideFAB`), когда: `hideNav` истинен, ИЛИ
  `todayLayout === "board" && путь === "/today"` (там кнопка заменена пунктирной
  пилюлей «Добавить задачу» в подвале колонки), ИЛИ путь `/overview` (там кнопки
  создания нет вовсе), ИЛИ открыта панель задачи на десктопе (`showTaskPanel`).
- **Свайп-назад** (`useSwipeBack`) подключён на всех НЕ-корневых вкладках (корневые —
  те, что входят в `NAV_ITEMS`, см. 2.1). На корневых вкладках свайп недоступен,
  фоллбэк при отсутствии истории — переход на `/overview`.

Десктопная ветка (`!isMobile`, вне телефона, не относится к SwiftUI-порту напрямую,
приводится для полноты картины): `SideNav` слева, контент по центру
(`max-w-[880px] mx-auto`), справа — панель деталей задачи на ширине ≥1280px, если
открыт `/task/:id`; FAB справа (`right: 18px`) с долгим нажатием, которое на `/projects`
ведёт на `/projects?create=1`, на `/notes` — на `/notes?create=1`.

## 2. Нижняя навигация и кнопка создания

### 2.1 Активная схема: BottomNav + AnimatedTabBar + CreateMenu

**Состав вкладок** (`lib/navItems.ts`, порядок ровно такой, ровно 4 пункта):

| #   | path        | label            | icon                                                                                                                                                     |
| --- | ----------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `/today`    | **Сегодня**      | `todayDate` — живая иконка календаря: рисует текущее число внутри (SVG с `<text>`), обновляется раз в сутки в 00:00:05 и при возврате приложения из фона |
| 2   | `/overview` | **Обзор**        | `home`                                                                                                                                                   |
| 3   | `/upcoming` | **Планирование** | `calendarSmall`                                                                                                                                          |
| 4   | `/chat`     | **Чат**          | `chat`                                                                                                                                                   |

Ряд иконок **без подписей** под ними (только `aria-label` для доступности), без
«горбика»/приподнятой кнопки — просто ряд, активная вкладка подсвечивается цветом
(красный акцент). По центру ряда, строго посередине (2 пункта слева, 2 справа) —
круглая кнопка создания.

Если текущий путь не входит в 4 пункта выше (например, `/settings`, `/task/:id`,
`/projects`) — панель всё равно показана, но ни одна вкладка не подсвечена
(`navIndex = -1`, без отображаемого «активного» состояния).

**Бейдж на вкладке «Сегодня»**: числовой счётчик поверх иконки — количество активных
задач со сроком «сегодня» (`due_date === todayStr() && status === "active"`).
Правило показа: бейдж гаснет **после первого захода** на `/today` в текущий
календарный день и не появляется заново до полуночи, даже если список задач
изменился. Флаг хранится в `localStorage` под ключом `taskflow_today_badge_seen_date`
(значение — дата в формате `YYYY-MM-DD`), переживает перезапуск приложения.

**Центральная кнопка** — SVG «плюс» (доворачивается в крестик, когда меню открыто),
короткий тап переключает открытие/закрытие `CreateMenu`.

**CreateMenu** — плоское меню «что создать», раскрывается **вверх** от центральной
кнопки (анимация из нижней точки). Подложка ловит тап мимо и закрывает меню без
затемнения фона. Карточка — 3 пункта, дословно:

| Иконка     | Заголовок   | Подпись                   | Переход                                                                   |
| ---------- | ----------- | ------------------------- | ------------------------------------------------------------------------- |
| `check`    | **Задача**  | **Со сроком и шагами**    | `/task/new?due=today` (если открыто с экрана `/today`), иначе `/task/new` |
| `notebook` | **Заметка** | **Запись в дневнике**     | `/notes?create=1`                                                         |
| `inbox`    | **Проект**  | **Задачи и документация** | `/projects?create=1`                                                      |

Esc закрывает меню (для браузерной версии).

### 2.2 FanMenu — в коде есть, но НЕ активен

Полноценный компонент, ждущий переключения флага `MOBILE_NAV_STYLE` в
`Layout.tsx` на `"fan"`. Если/когда его включат, поведение такое:

- Триггер-кнопка 64×64px, пункты веера — кружки 56×56px, дуга радиусом 100px на
  180°, шаг между пунктами = `180° / (n − 1)` (при 4 пунктах `NAV_ITEMS` — по 60°).
- **Короткий тап** по триггеру — открывает/закрывает веер (toggle), пункты
  появляются со стаггером 50мс между собой, spring-анимация.
- **Долгое удержание** (400мс) — минует открытие веера и сразу создаёт: на
  `/projects` → `/projects?create=1`; на `/notes` → `/notes?create=1`; на `/today` →
  `/task/new?due=today`; в остальных случаях → `/task/new`.
- Пунктов «Добавить» и «Настройки» в веере нет (сознательно убраны).
- Без затемнения фона при открытии.
- Пункты веера — те же 4 из `NAV_ITEMS` (см. 2.1).

### 2.3 SideNav (десктоп)

Вертикальный список тех же 4 пунктов `NAV_ITEMS`. Активный пункт — красный текст без
подложки. Бейдж «Сегодня» — красный кружок с числом (та же логика показа, что в 2.1).

## 3. Общие компоненты (переиспользуемые части экранов)

### 3.1 `ScreenHeader`

Шапка — `position: fixed` (НЕ sticky), с распоркой в потоке документа, чтобы контент
не заезжал под неё. Два слоя backdrop-blur с затуханием + цветной градиент-подложка
под цвет фона. Общий отступ снизу шапки — 16px.

- `variant="large"` — заголовок слева, 28px/жирный (используется, где заголовок —
  просто текст экрана).
- `variant="compact"` — заголовок **абсолютно отцентрирован**, 17px/полужирный
  (используется в TaskDetailScreen/TaskFormScreen).
- Стрелка «назад» (leading) появляется **сама**, если экран не входит в корневые
  вкладки и leading явно не передан.
- `below` — опциональная строка под заголовком (например, подпись месяца в
  «Планировании» или полоса дней в трёхдневном виде).
- Шапка следует за высотой системной клавиатуры iOS через
  `transform: translateY(var(--vv-top, 0px))`, привязанный к `visualViewport`.

### 3.2 `Loading` / `ErrorBanner`

- `Loading` — текст **всегда** дословно: «**Загрузка…**». Варианты `inline`/`block`
  различаются только отступами, не текстом.
- `ErrorBanner` — `variant="inline"`: маленький коралловый текст с сообщением
  ошибки; `variant="block"`: коралловая плашка с иконкой info и тем же текстом.
  Конкретные тексты fallback — см. по экранам ниже.

### 3.3 `TaskRow` — строка задачи в списке

Используется на «Сегодня» (список), в старом «Входящих» и «Планировании» (список).
Порядок содержимого строки **сверху вниз**:

1. (опц.) бейдж проекта — `#Название`, цвет проекта, без заливки фона.
2. Строка заголовка: название задачи + (опц., если есть исполнитель) аватар 20px
   слева от текста.
3. (опц.) описание — не более 2 строк, дальше `line-clamp-2` обрезает.
4. (опц.) `AgentStateTag` в «плоском» виде (цветное слово без плашки-подложки) — см.
   3.11.
5. Ряд бейджей (в этом порядке, каждый опционален):
   - подзадачи «N/M»;
   - флажок приоритета (P1–P3 отображаются, P4 — нет);
   - «**Просрочено, {формат даты}**» — красная пилюля (только для просроченных);
   - обычная дата + «**· N дн.**»;
   - метки — цветные пилюли с иконкой тега.

**Свайп влево** открывает синюю кнопку «**Изменить**» (`#007AFF`, иконка `edit`) →
переход на `/task/:id/edit`.
**Свайп вправо** открывает красную кнопку «**Удалить**» (`#FF3B30`, иконка `trash`) →
показывает confirm-шторку:

- Заголовок: «**Удалить задачу?**»
- Подзаголовок: «**«{название}» будет удалена безвозвратно**»
- Кнопки: «**Удалить**» (красная) / «**Отмена**»

Пороги жеста: ширина каждой кнопки действия `ACTION_W = 84px`.

- Открытие свайпа (из закрытого состояния): смещение `> 36px` **или** скорость
  `> 280 px/с`.
- Закрытие свайпа (когда уже открыт): обратное смещение `> 25px` **или** скорость
  `> 250 px/с`.
- За пределами `ACTION_W` — резиновое сопротивление (rubber-band): `over × 30 / (30 + over)`
  сверх ширины кнопки.

Пропы по умолчанию: `showAgentState=true`, `maxLabels=Infinity`, `showDueBadge=true`,
`showSubtasksBadge=true`, `showAvatar=true`, `showProjectBadge=true` — экраны
переопределяют то, что им не нужно (например, «Планирование» передаёт `maxLabels=1
showDueBadge=false`).

### 3.4 `TaskBoard` — доска колонок

Используется на «Сегодня» (вид «Доска»). Колонки прокручиваются горизонтально со
`snap-center`, ширина колонки — `min(calc(100vw − 40px), 632px)`; при единственной
колонке — `min(calc(100vw − 32px), 608px)`, центрирована.

Карточка колонки (BoardCard), сверху вниз: (опц.) бейдж проекта → заголовок + аватар
→ описание (обрезано до 1 строки) → `AgentStateTag` (компактный, плоский) → нижний
ряд (подзадачи N/M, дата, метка).

**Drag-and-drop:**

- Карточка перетаскивается целиком, без отдельного грип-хендла.
- Сенсоры dnd-kit: мышь — активация после сдвига на `4px`; палец — активация после
  задержки `200ms` **и** сдвига `8px` (`TouchSensor { delay: 200, tolerance: 8 }`).
- Сортировка **внутри** колонки работает всегда — пишет поле `position`.
- Перенос карточки **между** колонками пишет `project_id` только если у **всех**
  колонок доски задан `dotColor` (доска «по проектам»). На доске «Сегодня» (колонки
  без `dotColor`) перенос между колонками карточку просто **отскакивает назад** — на
  сервер ничего не пишется.

Пустая колонка: «**Нет задач**» (пунктирная рамка).
Пустая доска целиком: пропом задаётся `emptyMessage`, по умолчанию —
«**Пока нечего показать**» (для старого InboxScreen передавался текст «**Задач пока
нет**»).

Горизонтальная прокрутка запоминается между заходами через `sessionStorage`, ключ
`taskboard-scroll:{pathname}` (сбрасывается при закрытии вкладки браузера/выгрузке
процесса — это НЕ персистентное хранилище между запусками приложения).

### 3.5 `DayHours` — вид «по часам» / «один день» / «три дня»

Используется на «Сегодня» (вид «Один день», одна колонка) и на «Планировании» (вид
«Три дня», три колонки: сегодня/+1/+2).

**Числа сетки** (все — замеры, не круглые величины):

- Высота часа `HOUR_H = 124/3 ≈ 41.33px`.
- Ширина левой колонки с подписями часов `GUTTER_W = 161/3 ≈ 53.67px`.
- Привязка перетаскивания ко времени — шаг `SNAP_MIN = 15` минут.
- Минимальная высота плашки задачи `MIN_H = 24px` (чтобы короткая задача не
  схлопывалась в линию).

**Состав сверху вниз:**

1. Приклеенный (sticky) под шапкой пул задач **без времени** — единая карточка со
   строками: флажок приоритета + счётчик подзадач «N/M» + название. Задачи оттуда
   перетаскиваются на сетку ниже.
2. Часовая сетка на 24 часа (00:00–24:00). Плашки задач со временем (`TimedBlock`) —
   сплошная заливка цветом проекта, тёмный текст `#141414` (для контраста WCAG на
   светлой заливке), без кружка-маркера. Если длительность не задана, низ плашки
   размыт градиентной маской.
3. Линия «сейчас» (`NowLine`) — красная, проходит через все колонки, с подписью
   времени, пересчитывается раз в минуту.

**Drag-and-drop:** перетаскивание плашки/строки из пула на сетку вызывает
`onSchedule(id, date, time)`, время привязывается к сетке `SNAP_MIN` (15 минут).
Дата берётся от колонки, куда отпущена задача (в трёхдневном виде можно перенести
задачу на другой день простым переносом в другую колонку). Если у задачи раньше не
было длительности — при постановке на сетку ей присваивается 15 минут по умолчанию.

**Горизонтальный свайп** между днями (порог 45px) вызывает `onPrevDay`/`onNextDay` —
доступен только там, где эти пропы переданы (в одноколоночном виде «Сегодня»; в
трёхколоночном виде «Планирования» навигации свайпом нет, там своя навигация по
неделе).

Пустое состояние (нет ни одной задачи со временем): «**На время пока ничего не
назначено**».

При открытии экран автоматически проскраливает к текущему часу с запасом 120px
сверху.

### 3.6 `UpcomingCalendar` — WeekGrid / MonthGrid / DaySheet / DayStrip / MiniMonth / TaskChip

Компоненты видов «Неделя»/«Месяц»/раскрытого дня для «Планирования» (см. 5.2).
Неделя **везде** начинается с понедельника.

- **WeekGrid** — сетка 2×4: первая ячейка — `MiniMonth`, остальные 7 — дни недели
  списком задач-чипов. Горизонтальный свайп меняет неделю, порог `SWIPE_MIN_PX = 70px`
  (и требование, что горизонтальное смещение весомее вертикального — не сработает
  при почти вертикальном жесте).
- **MonthGrid** — непрерывная лента недель (Google Calendar-style). Высота строки
  недели фиксирована: `MONTH_ROW_H = 128px`. При открытии сразу подгружается
  `WEEKS_INITIAL_PAST = 8` недель в прошлое и `WEEKS_INITIAL_FUTURE = 16` недель
  вперёд; дальнейшая подгрузка идёт чанками по `WEEKS_CHUNK = 12` недель через
  `IntersectionObserver` при прокрутке к краю списка.
- **Лимит чипов задач в ячейке дня месяца**: `MONTH_CHIP_LIMIT = 4` — если задач
  больше, показываются первые 4, остальные не рисуются построчно (день можно
  раскрыть отдельно).
- Раскрытый день в месячном виде вставляется полосой (`DayStrip`) между своей
  неделей и следующей, без кнопки «Свернуть»; день недели пишется полным словом.
- **DaySheet** (используется только в недельном виде, при тапе по дню недели) —
  bottom sheet: заголовок = дата, кнопка «**Готово**» закрывает; свайп влево/вправо
  переключает день, порог 60px.
- **TaskChip** — компактная плашка задачи в ячейке: одна строка (отметка + название
  - время справа), время печатается интервалом через `formatTimeRange` (см. 4.1).
- Порог начала раскрытия/сжатия ленты-календаря свайпом «за краюшек» (только в виде
  «Список»): `CAL_DRAG_THRESHOLD = 48px` (после какого сдвига жест считается
  завершённым и лента доводится до конца), минимальная высота во время перетаскивания
  `CAL_DRAG_MIN_H = 36px`.

Тексты пустых состояний: «**Нет задач на эту дату**» (выбранная дата в списке без
задач), «**Ничего не запланировано**» (`DayStrip`, пустой день), «**На этот день
ничего не запланировано**» (`DaySheet`, пустой день).

### 3.7 Поля формы задачи (`TaskFields.tsx`)

Общие для TaskFormScreen (создание/правка) и частично TaskDetailScreen (read-only
отображение). Визуальная база — `Card` (карточка `bg-card rounded-2xl`, разделители
между строками) + `FieldRow` (иконка слева, подпись, значение справа, шеврон).

**PriorityField** — свёрнутый вид: `FieldRow` с флажком цвета текущего приоритета +
название приоритета тем же цветом (без пилюли). Разворачивается в список из 4
вариантов, каждый — кружок с меткой P1–P4 цветом приоритета + название + галочка у
выбранного. Источник данных приоритетов — `lib/priority.ts` (см. 4.2).

**DueDateField** — поле «**Срок**» (без времени) либо «**Срок и время**» (когда
передан проп времени — так его использует TaskFormScreen). Свёрнутая строка
показывает:

- «**Не установлен**» — если дата не задана;
- `{formatDueLabel}` — если задана дата без времени (например «Сегодня, 31 авг.»);
- `{formatDueLabel} · {формат интервала}` — если задано и время (например
  «Сегодня, 31 авг. · 13:45—14:30»).

Развёрнутая панель, сверху вниз:

1. Две быстрые кнопки в ряд: «**Сегодня**» / «**Завтра**».
2. Мини-календарь месяца: стрелки навигации по месяцам (доступен и горизонтальный
   свайп по календарю), дни недели «Пн Вт Ср Чт Пт Сб Вс», выбранный день —
   красный кружок.
3. Если поле объединено со временем — блок «**Во сколько**» (подпись «сначала
   выберите день», пока дата не выбрана): барабан времени `TimeWheel` — единственный
   барабан времени начала, шаг **15 минут**, центральная пилюля показывает не одно
   время, а сразу интервал («12:15—12:45»), если задана длительность. Визуально
   барабан имитирует цилиндр (строки сжимаются к краям, как в системном пикере
   iOS): угол между соседними строками 25.5°, радиус цилиндра ≈73.3pt. Виброотклик:
   лёгкий тик на каждое деление 15 минут, более выраженный — на переходе через
   ровный час.
4. Если день уже выбран — блок «**Продолжительность**»: горизонтальная лента-капсула
   с 6 фиксированными значениями: **15м, 30м, 45м, 1ч, 2ч, 3ч** (значения в минутах:
   15/30/45/60/120/180). Повторный тап по уже выбранному значению снимает
   длительность (возврат к «без длительности»). Слева от выбранного значения —
   заливка-«шлейф», затухающая к началу ленты.
5. Кнопка снизу (только если дата задана): «**Убрать дату и время**» (если задано
   время) либо «**Убрать дату**» (если время не задано). При снятии даты автоматически
   обнуляется и время — сервер не принимает время без срока.

**LabelsField** — свёрнутый вид: `FieldRow` с иконкой тега, значение — до 2 первых
выбранных меток пилюлями + «+N» для остальных, либо «**Нет**», если меток не
выбрано. Развёрнутая панель — облако всех доступных меток пилюлями, тап
переключает выбранность; если меток в системе нет: «**Нет доступных меток**».

**SubtaskRow** (только в режиме правки задачи, `edit`) — строка подзадачи: галочка
слева, если подзадача выполнена (сама отметка выполненности здесь недоступна —
только в карточке задачи), название (тап открывает переименование инлайн, Enter —
подтвердить, Esc — отмена), крестик справа — удаление. Строка целиком перетаскиваема
(drag-reorder через dnd-kit) — грип-хендла нет, старт драга — удержание пальцем или
ведение мышью самой строки.

**AddSubtaskRow** — поле ввода «**Добавить подзадачу...**» (плейсхолдер), кнопка-
галочка справа появляется, только когда в поле есть текст; Enter добавляет
подзадачу и очищает поле.

### 3.8 `RescheduleSheet` — массовый перенос просроченных задач

Bottom sheet, открывается кнопкой «Перенести» с колонки «Просрочено» на доске
«Сегодня» (см. 5.1).

Шапка шторки: крестик (закрыть) слева, «**Срок**» по центру, круглая красная
галочка справа — подтверждает дату, выбранную в календаре ниже (недоступна, пока
дата не выбрана или пока идёт перенос).

Быстрые варианты (применяются сразу по тапу, без отдельного подтверждения):

- «**Сегодня**» (с подписью дня недели справа)
- «**Завтра**»
- «**На выходных**» (ближайшая суббота)
- «**Следующая неделя**» (ближайший понедельник)
- «**Без срока**» (снимает дату целиком)

Ниже — календарь месяца (переключение месяца стрелками, тап по дню ставит
предварительный выбор — красная точка, требует подтверждения галочкой в шапке).

Индикатор процесса во время массового переноса: «**Переносим {done} из
{total}…**» (N параллельных запросов на изменение задачи — единого «массового»
эндпоинта на сервере нет).

Ошибка: «**Не удалось перенести {N} из {всего} задач. Остальные уже перенесены —
попробуйте ещё раз.**»

### 3.9 `TaskFilterSheet` / `TaskFilterButton`

`TaskFilterButton` — иконка `filter` 44×44px, **без** индикатора «что-то выбрано»
(намеренно убран). Используется на «Сегодня» и «Планировании» (и в старом,
неактивном InboxScreen).

Шторка `TaskFilterSheet`: крестик слева, «**Фильтры**» по центру, «**Сбросить**»
справа (неактивна, если ничего не выбрано). Раскрывающиеся секции (карточки с
`FieldRow`):

1. **Проект** — вариант «Все проекты», пусто → «Нет задач с проектом».
2. **Метка** — вариант «Все метки», пусто → «Нет задач с метками».
3. **Исполнитель** — вариант «Все исполнители» + «Без исполнителя» (если применимо),
   пусто → «Нет данных об исполнителях».
4. **Показывать выполненные** — переключатель (toggle), без подпунктов; влияет
   только на видимость, не на остальные фильтры.
5. (опционально — только на «Сегодня»/«Планировании», через `plannerProjects`)
   **Показывать в разделе** — постоянный многовыборный список проектов, видимых в
   ежедневнике. Подпись: «**Выбери проекты, задачи которых показывать в этом
   разделе. По умолчанию раздел показывает только задачи без проекта.**» Пусто →
   «Нет проектов для добавления» либо «Все проекты уже в разделе».

Фильтры (проект/метка/исполнитель/показ выполненных) **не персистятся** — это
локальный `useState` экрана, сбрасывается при уходе с экрана и возврате. Секция
«Показывать в разделе» персистится отдельно, через стор (см. 4.4).

### 3.10 `PlannerProjectChips` — полоска чипов под шапкой

Показана на «Сегодня» и «Планировании» под шапкой (внутри sticky-обёртки), только
если список видимых проектов не пуст (плюс неснимаемый чип «Входящие»). Состав
слева направо:

1. Неснимаемый чип «**Входящие**» — не интерактивный, обозначает базовый режим
   «только входящие».
2. Чипы видимых проектов, цвет фона/текста — цвет проекта (заливка 15% альфы).
   Тап по чипу сейчас **ничего не делает** (обработчик `onRemove` не подключён,
   удаление чипов через саму полоску пока не реализовано — для этого нужен picker
   в `TaskFilterSheet`, секция «Показывать в разделе»).
3. Кнопка «**+ проект**» (пунктирная рамка) — открывает `TaskFilterSheet` с сразу
   раскрытой секцией «Показывать в разделе».

## 4. Библиотеки — источники текста, форматов и данных

### 4.1 `lib/date.ts` — форматы дат (импортируется по всему приложению)

- **«Сегодня» вычисляется по московскому времени** (`Europe/Moscow`), а не по
  локальной таймзоне устройства — так задача с due_date «сегодня» не «уезжает» в
  «вчера/завтра» на устройстве в другом часовом поясе. Хранение в БД — UTC, это
  касается только отображения.
- `MONTHS_SHORT` — родительный падеж без точки: `янв, фев, мар, апр, мая, июн, июл,
авг, сен, окт, ноя, дек`.
- `formatDueLabel(date)` — «Срок»-подпись:
  - сегодня → «**Сегодня, {D} {мес}.**»
  - завтра → «**Завтра, {D} {мес}.**»
  - другой год → «**{D} {мес} {ГГГГ}**» (без точки)
  - текущий год, не сегодня/завтра → «**{D} {мес}.**»
- `formatDaysLeft(date)` — короткая подпись «сколько осталось»: `0` → «**сегодня**»,
  `1` → «**завтра**», `-1` → «**вчера**», иначе — «**осталось N {день/дня/дней}**»
  (будущее) или «**просрочено на N {день/дня/дней}**» (прошлое); склонение по
  стандартным русским правилам (11–14 всегда «дней»).
- `formatRelativeTime(sqliteDatetime)` — для комментариев/уведомлений/активности:
  `< 1 мин` → «**только что**», `< 60 мин` → «**N мин. назад**», `< 24 ч` → «**N ч.
  назад**», `1 сутки` → «**вчера**», иначе → «**N дн. назад**».
- `formatAbsoluteTime(sqliteDatetime)` — абсолютное время рядом с относительным:
  сегодня → «**ЧЧ:ММ**»; раньше → «**D мес, ЧЧ:ММ**» (год не пишется).
- `formatTimeRange(start, durationMin)` — «**13:45**» без длительности, «**13:45—
  14:30**» с ней. Печатается ВЕЗДЕ интервалом, а не «начало + отдельно
  длительность» — так пользователю не нужно складывать в уме. Переход через
  полночь заворачивает конец на следующие сутки без указания второй даты.
- `partitionOverdueToday(tasks, today)` — единая точка деления списка на
  «просроченные» (due_date < today, отсортированы по due_date по возрастанию — самые
  старые просрочки сверху) и «на сегодня» (due_date === today). Используется и
  списком, и доской на «Сегодня» — оба вида не могут разойтись в том, что считать
  просрочкой.

### 4.3 `lib/taskFilters.ts` — форма фильтров и правила применения

```
TaskFilters = {
  projectId: string | null      // null = все проекты
  labelId: string | null        // null = все метки
  assigneeKey: string | null    // null = все, "__none" = без исполнителя, иначе id
  showCompleted: boolean        // по умолчанию false
}
```

- Дефолт (`DEFAULT_TASK_FILTERS`) — все `null`, `showCompleted: false`.
- **Выполненные задачи скрыты по умолчанию** на всех трёх экранах, где используются

  не что уже сделано.
- Списки опций для пикеров (`buildProjectOptions`/`buildLabelOptions`/
  `buildAssigneeOptions`) строятся из ПОЛНОГО (ещё не отфильтрованного) набора задач
  экрана — так вариант не исчезает из списка только потому, что сейчас активен
  другой фильтр, дающий с ним пустое пересечение.

## 5. Экраны

### 5.1 «Сегодня» (`/today`)

**Назначение:** рабочий список задач на сегодняшний день + то, что просрочено, + то,
что ждёт решения по агентским задачам.

**Шапка** (`variant` определяется видом — заголовок и есть дата):

- Заголовок: «**{День недели}, {D} {мес}.**» (например «Четверг, 20 авг.») — для
  вида «Один день» дата берётся от текущей просматриваемой колонки (`activeHourDate`),
  для остальных видов — от сегодняшнего дня.
- Actions справа: кнопка-фильтр (`TaskFilterButton`, см. 3.9) + кнопка «Ещё» (иконка
  `dots`, `aria-label="Ещё"`) → `ActionsMenu` с пунктами (текущий вид отмечен
  красным полужирным): «**Список**» / «**Доска**» / «**Один день**» / «**Поиск**»
  (последний ведёт на `/search`, остальные три переключают `taskLayout.today`).
- Под шапкой (если список видимых проектов не пуст) — `PlannerProjectChips` (3.10).

**Три вида** (persist в `taskLayout.today`):

**list** (список), секции сверху вниз, задача рисуется РОВНО в одной секции по
приоритету:

1. `AppleCalendarEvents` — события календаря на сегодня (вне этой части спеки).
2. «**Ждут вас**» (иконка бота, заголовок 17px/полужирный) — задачи с
   `isWaitingForUser`, заблокированные впереди готовых к проверке.
3. «**Просрочено**» (заголовок красным) — задачи из `partitionOverdueToday().overdue`.
4. Дата-заголовок `formatDueLabel(today)` — показывается, только если выше уже были
   секции «Ждут вас»/«Просрочено» (иначе дата и так видна в шапке экрана).
5. Задачи на сегодня, обычными `TaskRow`.

**board** (доска, `TaskBoard`), колонки в этом порядке:

- «**Ждут вас N**» — опционально, только если таких задач больше 0.
- «**Просрочено N**» — опционально; заголовок красным, кнопка в шапке колонки
  «**Перенести**» → открывает `RescheduleSheet` (3.8).
- «**Сегодня**» — присутствует всегда; подвал колонки — пунктирная кнопка
  «**Добавить задачу**» → `/task/new`.
  Доска на «Сегодня» **не группируется по проектам** — колонки без `dotColor`, поэтому
  перенос карточки между колонками не пишет `project_id` (см. 3.4).

**hours** («Один день», `DayHours` с одной колонкой): показывает `activeHourDate`,
свайп/навигация меняет день. Задачи с агентским назначением (`isAgentAssignedTask`)
из этого вида исключены. Постановка на сетку пишет `start_time` + `due_date` +
`duration_min = 15` (если раньше не было).

**Состояния:**

- Загрузка: `<Loading/>` → «**Загрузка…**».
- Ошибка: `ErrorBanner`, fallback-текст — «**Не удалось загрузить задачи**».
- Пусто и нет активных фильтров (`trueEmpty`, только вид «Список»): SVG-иллюстрация
  смайлика + заголовок «**Чёткое видение грядущего дня**» + текст «**Задачи на
  сегодня появятся здесь, когда вы назначите дедлайн.**».
- Пусто из-за фильтров (`filteredEmpty`): «**Под выбранные фильтры ничего не
  подошло**» + кнопка «**Сбросить фильтры**».

**Источник данных:** общий React Query кэш задач (`useTasks()`, ключ `["tasks"]`),
локальная фильтрация/группировка через `useMemo` с `lib/taskFilters.ts` (4.3) и
`lib/date.ts` (4.1).

**Шторки, подключённые на экране:** `RescheduleSheet` (3.8), `TaskFilterSheet` (3.9).

### 5.2 «Планирование» (`/upcoming`)

**Назначение:** просмотр и планирование задач вперёд — календарём.

**Шапка:** заголовок всегда «**Планирование**» (не меняется по виду). Actions —
`TaskFilterButton` + «Ещё» → `ActionsMenu` с 4 пунктами (текущий вид — красным
полужирным): «**Список**» / «**Неделя**» / «**Месяц**» / «**Три дня**».

**Четыре вида** (persist в `upcomingLayout`):

**list** — лента-выборщик даты сверху (сворачивается в узкую полосу недели жестом
«за краюшек» или кнопкой, см. `CAL_DRAG_THRESHOLD` в 3.6) + список задач,
сгруппированных по датам со `sticky`-заголовками дат, плюс события календаря
(`AppleCalendarEvents`). `TaskRow` здесь с `maxLabels=1 showDueBadge=false`.

**week** — `WeekGrid` (3.6): сетка 2×4, горизонтальный свайп меняет неделю (порог
70px).

**month** — `MonthGrid` (3.6): непрерывная лента недель, раскрытие дня —
`DayStrip`, вставляется между строками недель.

**hours** («Три дня») — `DayHours` с тремя колонками (сегодня/+1/+2), своя нежёсткая
(не sticky-обёрнутая) шапка с полосой дней под заголовком.

**Состояния** (общие для всех 4 видов — блок рендерится один раз, до ветвления по
`view`, поэтому одинаково виден и в «Список», и в «Неделя»/«Месяц»/«Три дня»):

- Загрузка: `<Loading/>` → «**Загрузка…**».
- Ошибка: `ErrorBanner`, fallback-текст — «**Не удалось загрузить задачи**».
- Пусто (список без выбранной даты, фильтры вычистили всё): «**Под выбранные
  фильтры ничего не подошло**» + кнопка сброса.
- «**Нет задач на эту дату**» (список, выбранный день пуст), «**Ничего не
  запланировано**» (`DayStrip`, пустой день в месячном виде), «**На этот день ничего
  не запланировано**» (`DaySheet`, пустой день в недельном виде).

**Источник данных:** тот же общий кэш `useTasks()`, что и «Сегодня»; своя группировка
по датам (`groupByDate` из `UpcomingCalendar.tsx`).

### 5.3 «Обзор» (`/overview`)

**Назначение:** стартовый экран приложения (первое, что видит пользователь после
входа). Только карточки-переходы, без собственного списка задач.

**Шапка:** заголовок «**Обзор**», actions — только иконка поиска → `/search`.

**Тело сверху вниз:**

1. Сетка 2×2 карточек агентского статуса: **В работе** / **На проверке** /
   **Заблокированы** / **Пропали** — каждая ведёт на `/agent-work?focus=...` с
   соответствующим фильтром.
2. Карточка «**Сводка недели**» + бейдж «**Second Brain**» + подпись «**Победы,
   хвосты и фокус на цели недели**» — открывает `WeeklySummaryModal` (вне этой части
   спеки).
3. Список карточек-переходов:
   - «**Проекты**» / «Задачи по проектам и документация» → `/projects`
   - «**Уведомления**» / «История событий и напоминаний» → `/notifications`
   - «**Активность и статистика**» / «Графики продуктивности и выполненные задачи»
     → `/activity`
   - «**Настройки**» / «Профиль, ИИ, сервер и внешний вид» → `/settings`

**Кнопки создания на этом экране нет** (FAB скрыт, `fabHiddenOnOverview`).

**Состояния: на этом экране их сознательно нет.** Счётчики сетки 2×2 считаются на
клиенте (`useMemo` по `agent_state`/`agent_stale`/`status`) из уже загруженного
общего кэша `useTasks()` (тот же кэш, что у «Сегодня»/«Планирования»/карточки
задачи) — экран не читает `isLoading`/`error` из этого запроса вообще. Пока кэш
пуст (самый первый заход в приложение до первого ответа сервера), все 4 счётчика
молча показывают 0, отдельного индикатора загрузки или баннера ошибки нет.

### 5.4 Карточка задачи (`/task/:id`)

**Назначение:** просмотр задачи (только чтение полей — правка через отдельный
маршрут `/task/:id/edit`), отметка подзадач прямо здесь, лента комментариев.

**Источник данных:** сама задача — отдельный запрос `useTask(id)` (не общий список
`useTasks()`, а точечный GET по id), проекты — `useProjects()`, текущий пользователь
— `useCurrentUser()`; изменения идут через `useUpdateTask`/`useDeleteTask`
(задача), `useUpdateSubtask`/`useSubtaskWork` (подзадачи), `useAddComment`
(лента).

**Шапка:** `variant="compact"` (заголовок в центре пустой/не показан — сама задача
служит заголовком тела). Actions — 3 кнопки:

- «Вывести в Dynamic Island» (иконка `activity`) → toast «**Задача выведена в
  Dynamic Island**» (или сообщение об ошибке при неудаче).
- «Сохранить как шаблон» (иконка `bookmark`) → toast «**Задача сохранена в
  шаблоны**».
- «Удалить задачу» (иконка `trash`, коралловый цвет) → confirm: «**Удалить задачу
  без возможности отмены?**»

**Тело сверху вниз:**

1. (опц.) бейдж проекта.
2. Заголовок задачи (h1, 20px/полужирный) + флажок приоритета справа.
3. (опц.) описание.
4. (опц.) вложения задачи (`AttachmentView`, вне этой части).
5. Блок метаданных (карточки `bg-card rounded-xl`):
   - дата+время («Сегодня, 19 авг. · 13:45—14:30» — через `formatDueLabel` +
     `formatTimeRange`);
   - приоритет — флажок + название приоритета цветом (без пилюли, см. 4.2);
   - исполнитель — аватар + имя;
   - строка статуса агента, и если активный `agent_state` и текущий пользователь —
     владелец-создатель задачи — доп. действия владельца над агентской работой.
6. (опц.) метки — пилюли.
7. (опц.) табы «**Чек-лист (N)**» / «**Команда (N)**» — показаны, только если у
   задачи есть ОБА типа контента одновременно (и подзадачи, и что-то ещё, например
   назначенные агенты); иначе одна секция без табов.
8. Чек-лист подзадач (`SubtaskFeed`, вне этой части) — отметки прямо здесь.
9. Дочерние задачи — списком `TaskRow`.
10. Кнопки действий (в этом порядке приоритета, показывается одна): «**Завершить
    задачу**» (primary, если задача активна и без `agent_state`) / «**Открыть задачу
    заново**» (secondary, если задача уже завершена) — плюс отдельно «**Изменить**»
    (outline, показана всегда) → `/task/:id/edit`.
11. Заголовок «**Лента**» (13px) — поле ввода комментария (скрепка слева, текстовое
    поле, кнопка отправки справа), ниже — `TaskFeed` (комментарии + журнал событий в
    хронологическом порядке, вне этой части спеки).

**Кнопки «Закрыть задачу» нет** — закрытие сданной агентом задачи идёт только через
«Принять» внутри `TaskJournal` (вне этой части).

**Confirm при завершении задачи с незакрытыми подзадачами:**

- Заголовок: «**Завершить задачу?**»
- Текст (ровно 1 незакрытая подзадача): «**Шаг «{название}» останется невыполненным,
  а задача уйдёт в готовые.**»
- Текст (больше одной): «**Осталось невыполненных шагов: N. Завершить задачу?**»

**Состояния:**

- Задача не найдена (404 или id не резолвится): «**Задача не найдена**».
- Загрузка: `<Loading variant="block"/>` → «**Загрузка…**».

### 5.5 Форма задачи (`/task/new`, `/task/:id/edit`)

**Одна форма** обслуживает и создание, и редактирование — различие в заголовке
секции и в способе отправки патча (edit отправляет только «грязные» изменённые
поля, через сравнение с исходной задачей — `buildDirtyPatch`).

**Шапка:** `variant="compact"`, leading — крестик (X) → `navigate(-1)` (не сохраняет).
Actions — кнопка «**Готово**» (красная, 17px/полужирный), неактивна, если название
пустое (`!title.trim()`) или идёт сохранение; во время сохранения текст меняется на
«**Сохранение…**».

Если запущена структуризация текста через AI — плашка сверху тела: «**Структурирую
задачу…**» (`AiBusyPill`).

**Тело сверху вниз:**

1. Заголовок секции: «**Новая задача**» (создание) / «**Изменить задачу**» (правка).
2. (если в названии/описании уже есть текст) кнопка «**Структурировать с AI**» —
   градиентная пилюля с иконкой `sparkles`.
3. Textarea названия — плейсхолдер «**Название задачи**», авто-рост высоты по
   содержимому.
4. Заголовок «**Заметка**» + textarea описания — плейсхолдер «**Описание**».
5. Заголовок «**Подзадачи**» + список подзадач (в режиме создания — простой
   локальный массив строк с крестиком удаления без сохранения на сервер до отправки
   формы целиком; в режиме правки — перетаскиваемые строки `SubtaskRow`, см. 3.7) +
   `AddSubtaskRow` (3.7) для добавления новой.
6. Вложения (`AttachmentsField`, поведение разнится между созданием и правкой, вне
   подробного разбора этой части).
7. Карточка (`Card`) полей: `DueDateField` («Срок и время», см. 3.7), `FieldRow`
   «**Проект**» (раскрывающийся picker; пусто → «**Проектов пока нет**»),
   `PriorityField` (3.7), `LabelsField` (3.7).
8. Заголовок «**Назначить**» — picker исполнителя из списка агентов; пусто → «**Выбрать
   исполнителя**» с пунктирным кружком-плюсом. В списке у каждого агента (только
   для типа `ai`) — статус «**на связи**» / «**не в сети**».

**Диктовка:** одна кнопка-микрофон в плавающей панели над системной клавиатурой
(`MicKeyboardBar`) — пишет в поле, где последний раз стоял фокус (заголовок /
описание / поле подзадачи, отслеживается через `voiceTarget`). После завершения
диктовки под полем — подпись источника: «**Распознано Whisper на устройстве**» /
«**диктовка Apple**» / «**через сервер**» (в зависимости от `voiceSource`).

**Разбор маркеров при диктовке** (только в режиме создания, применяется по потере
фокуса поля названия): `#Проект`, `!приоритет`, `@Метка`, относительные даты
(«завтра» и т.п.) — через `parseDictation`.

**Правило по умолчанию:** новая задача создаётся **без срока**, кроме случая, когда
форма открыта с параметром `?due=today` (кнопка создания на экране «Сегодня»/
CreateMenu). При снятии даты автоматически сбрасывается и время/длительность.

**Состояния:**

- Не найдено (правка несуществующей задачи, 404): «**Задача не найдена**».
- Загрузка (правка, до подгрузки данных задачи): `<Loading variant="block"/>`.
- Ошибка сохранения: `ErrorBanner` (block).
- Ошибка загрузки справочников: `ErrorBanner` (block), текст: «**Не удалось загрузить
  проекты, метки или агентов. Проверьте соединение.**»
