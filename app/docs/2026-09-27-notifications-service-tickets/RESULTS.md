# Уведомления: раздел серверных сводок и прочтение

Решения владельца 27.09.2026:

- Дубли активности (вердикты, назначения, комментарии и смены статуса) убраны из уведомлений владельца на сервере; локальный фильтр также скрывает их из прогретого списка. Завершения сохранены согласно предыдущему указанию.
- «Серверные уведомления» — постоянная строка перехода с количеством, отдельная страница со списком сводок. Общая иллюстрация «Уведомлений пока нет» убрана. Загрузка, ошибка и пустой список отображаются внутри серверного раздела.
- Тонкая красная обводка 0,5 pt с opacity 0,45 означает непрочитанное уведомление любого уровня, включая info. Открытие полного разбора снимает обводку; ошибка обозначается уровнем error. Дублирующий значок тревоги удалён из превью и подробностей.
- Прочтение сохраняется через AppStorage на устройстве по id и ts сводки. Перезапуск сохраняет прочтение; новый ts снова показывает обводку. Сервис уведомлений не имеет подключённого API прочтения, синхронизация этого признака между устройствами не добавлена.
- Существующие переходы к диагностической задаче и выбор решения сохранены.

## Проверка

Сервер: 76 наборов / 586 тестов, TypeScript noEmit. Миграции 068/069 блокируют создание дублей для владельца; старые строки сохранены и скрыты в API. Резервная копия SQLite и проверка integrity_check выполнены до изменения.

iOS: Debug Simulator build — BUILD SUCCEEDED. Сборка установлена и запущена в iPhone Air Simulator. Проверка перехода и снятия обводки не подтверждена: интерфейс симулятора через CUA не реагирует на клики. Проверка на телефоне ещё не выполнена.

# LOCK-239: единая сводка и карточки со счётчиками

Начато Codex 27.09.2026, у него кончились лимиты; доделано и проверено Claude в тот же день.

## Что сделано

- **Сервер (.110, `~/infra-ops`):** `notification_digest.py` сводит все уведомления дня в одну «Сводку работы сервера» со счётчиками `ok_count / error_count / warning_count` и списком проверок `checks`; каждая критичная проблема дополнительно выносится отдельной карточкой «… — требуется внимание». Адрес — `GET /notifications/digest?date=ГГГГ-ММ-ДД`. Полный текст — прежний `/notifications/raw`, путь из ответа (`digest:ДАТА` или `critical:ДАТА:КЛЮЧ`). Коммит `ca5b561` в infra-ops: до него `notifications_api.py` вообще жил вне git.
- **iOS:** модель `ServiceTicketSummary` принимает `checks`, `revision` и счётчики; `ServiceTicketPresentation` даёт карточке человеческое название (без имён скриптов) и превью — первые две проблемы и «ещё N». Карточка и подробности показывают «штатно / ошибок / предупреждений». Клиент ходит в `/notifications/digest` вместо `/notifications/inbox`.

## Грабли

- Codex оставил сервис на старом коде: юнит работал с 01:52, файл правился в 16:41, поэтому `/notifications/digest` отдавал 404, а приложение уже было переключено на него. Сервис перезапущен (`systemctl --user restart notifications-api`).
