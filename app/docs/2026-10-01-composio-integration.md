# Composio в TaskFlow — 01.10.2026

## Реализовано

- В «Команда → роль → Инструменты Composio» добавлены включение, весь каталог или отдельные сервисы, поиск, состояние аккаунтов и подключение через HTTPS-ссылку авторизации.
- Owner-only API: GET/PATCH `/api/roles/:role/composio`, POST `/authorize`. Миграция `084_role_composio` хранит политику роли, без ключей.
- Одна политика работает в карточных `customTools` и MCP-конфигурации чата. По умолчанию подключение выключено; `null` означает весь каталог, `[]` — отсутствие разрешённых сервисов.
- Подключённые аккаунты относятся к владельцу. Сессия отделена по роли, контексту и режиму; повторные сообщения используют сохранённую сессию.
- В планировании сервер Composio фильтрует инструменты по `readOnlyHint`, исключает `destructiveHint`; локальный мост допускает только поиск, схемы и выполнение этого разрешённого набора. Sandbox и управление аккаунтами через модель выключены.
- Остановка передаёт отмену вызову, завершение закрывает MCP-процесс. Если включённый Composio недоступен, запуск выдаёт ошибку, не притворяется оснащённым инструментами.

## Решение архитектуры

Выбран общий stdio-мост к hosted MCP Composio. Альтернатива — отдельные адаптеры каждого провайдера моделей — потребовала бы разные регистрации в Pi и чате. Альтернатива — личный глобальный MCP-конфиг — нарушила бы политику ролей. Общий мост позволяет сохранить один набор прав и не передавать ключ приложению или модели. Цена решения: запуск дополнительного процесса и внешняя зависимость от Composio.

## Ключ и найденные ошибки

Новый ключ сохранён через `vault-add.py` в записи `API_COMPOSIO` зашифрованного хранилища .110. Каталог вернул HTTP 200. Значение не включено в исходники, этот документ или вывод команд.

Обычный `vault-run.py` буферизует stdout до выхода процесса, поэтому несовместим с постоянным stdio MCP. `composio_vault.py` использует существующие функции resolve/scrub vault-run, передаёт секрет только окружению дочернего процесса и маскирует его в потоковых строках. Тест проверяет ответ до завершения процесса и маскирование.

SDK 0.22.0 допускает `readOnlyHint` и `destructiveHint`, но не `createHint`/`updateHint`. Конфигурация проверяется по реальной схеме SDK. В пути с кириллицей точка входа определяется через `fileURLToPath`, не URL pathname.
