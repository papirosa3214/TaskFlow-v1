# Прозрачность постоянного контекста запуска роли

Статус: дизайн согласован владельцем 30.09.2026; код не начат.

## Цель первого этапа

В `Настройки → Команда` владелец открывает роль и видит полный набор
постоянных текстовых правил, которые добавляются к её запуску. Не нужно
читать исходники сервера и не нужно угадывать, почему роль ведёт себя именно
так.

Первый этап не показывает фактический запуск выбранной карточки: её
название, описание, комментарии, зависимости и история чата динамичны и
появятся отдельным этапом, когда их форма стабилизируется.

## Граница

Показываем только read-only слои:

| Вкладка | Содержимое | Область действия |
| --- | --- | --- |
| Роль | Разрешённая системная инструкция роли из `roles.prompt` либо fallback-файла | Все режимы |
| Общее | `LOCAL_EXECUTION_POLICY` | Все режимы |
| Задача | Шаблон обычного запуска и `AGENT_RULES` | Обычная задача |
| План | Шаблон запуска узла плана и `AGENT_RULES` | Узел плана |
| Чат | Постоянная обёртка чат-хода без истории и сообщения пользователя | Чат |
| Границы | Человекочитаемый список серверных ограничений и доступных инструментов | Все режимы либо явно указанная область |

Редактируемой остаётся только вкладка/поле «Инструкция» в уже существующем
`RoleEditorSheet`. Показ не создаёт вторую копию промпта и не позволяет
править общую политику, AGENT_RULES или серверные ограничения из телефона.

## Контракт сервера

Добавить один read-only endpoint:

`GET /api/roles/:role/runtime-context`

Он доступен тем же авторизованным пользователям, которым доступен профиль
роли. Ответ строится в server runtime из реальных источников, а не из копии
текстов на iOS:

```json
{
  "role": "architect",
  "layers": [
    {
      "id": "role",
      "title": "Роль",
      "scope": "Все режимы",
      "source": "roles.prompt" ,
      "editable": true,
      "text": "..."
    }
  ]
}
```

Для fallback-инструкции `source` явно сообщает
`scripts/role-prompts/architect.md`; для DB-override — `roles.prompt`.
Заготовки задачи, плана и чата возвращаются с нейтральными плейсхолдерами
(`{taskId}`, `{taskTitle}`, `{roleTitle}`), а не с данными конкретной задачи.

Сервер экспортирует небольшую чистую функцию-сборщик, которую использует и
endpoint, и тесты. Нельзя вручную переписать копии `LOCAL_EXECUTION_POLICY`,
`AGENT_RULES` или чат-обёртки внутри нового route.

## iOS-представление

В `RoleEditorSheet` появляется вторичное действие «Как запускается роль».
Оно открывает отдельную read-only шторку, чтобы редактор инструкции не
превратился в длинную смешанную форму.

Шторка получает массив слоёв endpoint-а и рисует горизонтальный системный
переключатель вкладок. Внутри вкладки:

1. название и область действия;
2. источник;
3. моноширинный, доступный для выделения текст;
4. короткая подпись «Редактируется в инструкции роли» только для слоя
   `Роль`; у остальных — «Это правило задаёт сервер».

Пустое/ошибочное состояние не подменяется заглушкой: показывается точная
ошибка загрузки. Слой неизвестного типа остаётся видимым как обычная вкладка,
чтобы новый серверный слой не оказался скрыт старым клиентом.

## Безопасность и согласованность

* Endpoint не отдаёт токены, MCP-конфиги, пути vault, историю чатов,
  содержимое задач или состояние сессий.
* Он показывает только постоянные правила и список имён доступных
  инструментов, если он уже безопасно показывается в профиле роли.
* Текст берётся при запросе: после смены DB-prompt, fallback-файла или
  серверной политики владелец видит новую правду без ручной синхронизации.
* Редактор `roles.prompt` остаётся единственным способом изменить личность
  роли. Сброс по-прежнему возвращает fallback-файл.

## Проверка реализации

1. Серверные тесты: DB-override и fallback, шесть слоёв, нейтральность
   шаблонов, отсутствие динамической задачи/истории в ответе, авторизация.
2. iOS-тесты декодирования и состояния вкладок.
3. XCUITest: `Настройки → Команда → Архитектор → Как запускается роль`,
   пройти все вкладки, снять attachment. Без мутаций `.110`.
4. Сборка iOS и server typecheck/tests по затронутым пакетам.

## Вне этапа

* Выбор карточки и просмотр собранного фактического контекста запуска.
* Редактирование MCP, skills или общей политики с телефона.
* Подключение skills/AGENTS.md к in-process runtime: это отдельная
  функциональная задача, не маскируемая экраном прозрачности.
