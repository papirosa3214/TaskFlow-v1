# Проверка редактора контекста ролей

Состояние 30.09.2026: реализация и проверка в Mac checkout. На `.110` новая версия **не выкладывалась**; живые инструкции и роли не менялись. Исходная работа архитектора сохранена в серверной ветке `codex/role-context-control` (cherry-pick `65c60a4` из `2531bedd`, завершение `97d9ccc`, ветка опубликована в Gitea).

## Реализовано

- «Команда → роль → Как запускается роль»: каталог действующих инструкций по группам, источник, режимы, исходный и действующий тексты; владелец может сохранить правку роли или команды, сбросить, посмотреть историю, восстановить. Разрешения и код инструментов только для просмотра.
- Серверный resolver хранит версию и историю, требует ожидаемую ревизию и возвращает 409 при конкурирующей правке. Сброс действительно снимает переопределение, поэтому роль снова наследует новую общую инструкцию.
- Задачи, чат Pi/MCP, описания инструментов, отдельные операции и голос Секретаря читают блоки общего каталога. Для Pi чат получает снимок выбранных SDK файлов и skills на запуск. Инструменты `read/bash/edit/write/grep/find/ls` сохранены. Исследователь получил `taskflow_report` во внутреннем запуске.
- Снимок manifest привязывает блок/источник/версию/хэш к запуску. Активная сессия или звонок не переопределяются посреди хода.

## Доказательства

| Проверка | Результат |
| --- | --- |
| Server `npm run build` | Успешно |
| Server `npx vitest run --reporter=dot` | 95 файлов, 700 тестов прошли |
| Python MCP `python3 -m unittest test_instruction_mcp` | 1 тест прошёл: snapshot меняет инструкции/описание, схема неизменна |
| iOS `xcodegen generate`, `xcodebuild ... build` | Сборка симулятора успешна |
| XCTest `RoleRuntimeContextTests` | 2 теста прошли: новые/старые DTO и сохранение черновика при конфликте |
| XCUITest `RoleInstructionControlUITests` | 2 теста прошли на финальной сборке 19:45: семантический переход из «Команды», сохранение в изолированной DEBUG-фикстуре и выбор общего scope. Снимки — [attachments/](attachments/) |
| Python voice worker unittest | Локально не запустился: в macOS Python нет `aiohttp`; Python-синтаксис проверен `py_compile`, Unix bridge покрыт серверным тестом |
| Web `npm run build` | Остановился на пяти ошибках других компонентов (`CollaborationPlanPanel`, `DayHours`, `UpcomingCalendar`, `LabelTasksScreen`). Изменённый `RoleContextSheet.tsx` дополнительных ошибок TypeScript не дал |

XCUITest использовал существующую авторизованную сессию симулятора и локальную `TASKFLOW_ROLE_CONTEXT_FIXTURE=1`; вызовов записи живых настроек не было. Осмотрены экспортированные screenshot attachments. Тумблер области заменён системным Picker после того, как тест показал, что он не меняет scope; финальный тест проверяет выбор «Вся команда» и появление пояснения.

## Ограничения до приёмки на live

- Пока сервер на `.110` не обновлён, iOS получает старый ответ `/api/roles/:role/runtime-context` и показывает прежний режим просмотра. Реальный ход роли с новым override после выкладки ещё не наблюдался.
- Встроенные Pi compaction/branch-summary и код extensions доступны как источник и ограничение, но текстом в этом редакторе не заменяются. Схемы инструментов и ACL тоже остаются кодом.
- Предлагаемые изменения устаревших правил перечислены в [text-audit.md](text-audit.md). Они не применялись к live без просмотра diff владельцем.
- Веб-сборка проекта сейчас имеет несвязанные ошибки; веб-редактор нельзя считать готовым к выкладке до их устранения.
