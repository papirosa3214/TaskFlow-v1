# Аватары ролей во всех поверхностях

## Причина

Предыдущая интеграция семи рисунков подключила `RoleAvatarAsset` только к `RoleAvatarView` экрана «Команда». Чаты и задачи пользуются другими аватарными компонентами; они не получали роль, а показывали серверное фото либо инициалы. Это не ошибка каталога картинок — связь между ID учётки и локальным ассетом отсутствовала в этих вызовах.

## Решение

- Добавлен круглый рисунок Секретаря `RoleAvatarSecretary` из одобренного владельцем варианта.
- Карта `RoleAvatarAsset` вынесена в общий компонент: семь `role_*` и `u-secretary` сопоставляются с восемью bundled imageset.
- `TFAvatar` принимает необязательный `userID`: для известного агента приоритетен локальный рисунок; для человека и неизвестной роли остаётся прежнее фото/инициалы.
- ID передаётся в список и ленту ролевых чатов, общий чат задачи, поле адресата, списки задач «Сегодня», «Предстоящие», проекты и метки. «Работа агентов» использует ту же карту.
- Секретарь — отдельная служебная учётка, а не роль из списка «Команда», поэтому её рисунок показывается в «Чатах», а не добавляется искусственно в список ролей.

## Проверка

`RoleAvatarAssetTests` проверяет соответствие восьми ID ассетам, наличие картинок в бандле и fallback для обычного пользователя/неизвестной роли. 28.09.2026 `xcodebuild ... -only-testing:TaskFlowTests/RoleAvatarAssetTests test` на iPhone 17 Pro Simulator завершился `TEST SUCCEEDED` (2/2). Для визуального принятия нужны кадры реальных чатов и задач после запуска приложения; компиляция сама по себе это не подтверждает.

### Прозрачный край

Семь первоначальных файлов оказались JPEG-изображениями под расширением `.png`: 1254×1254, но без alpha-канала, с белой подложкой. Это давало белую рамку после `clipShape(Circle())`. 28.09.2026 белый внешний фон переведён в alpha без изменения персонажей; все восемь итоговых PNG имеют alpha и размер 1254×1254. Тест дополнительно проверяет, что угол каждого bundled-ассета прозрачен. Повторный `RoleAvatarAssetTests` после конвертации: `TEST SUCCEEDED`, 2/2.
