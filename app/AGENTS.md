# Правило границ работы

## Нативные компоненты: постоянное правило владельца

Если владелец просит «нативный», «оригинальный» или «системный» компонент,
оставлять чистый SwiftUI-компонент без собственных `tint`, `background`,
`overlay`, `scaleEffect`, рамок, материалов и имитаций — если владелец прямо
не попросил именно эту настройку.

Нельзя называть компонент полностью системным, когда на нём остаётся хотя бы
одна такая визуальная настройка. При сомнении оставить чистый системный вид.

Работа ведётся только в `/Users/max/Проекты/TaskFlowNativeBuild`.

Исходный файл можно изменять только когда он указан в строке со статусом
`IN_PROGRESS` в `AGENT-WORK-SCOPES.md`. Всё вне такой строки неизменно.

## Проверка в симуляторе iOS: через XCUITest, не через ручной тап по скриншоту

Дойти до нужного экрана для проверки — через временный XCUITest, который
ищет элементы по `accessibilityIdentifier`/`label` (`app.buttons["..."]
.tap()`, `app.staticTexts["..."].tap()`), не через screenshot-инструмент
симулятора с ручным пересчётом координат под тап. У `tap`/`swipe` координаты
в points, а скриншот отдаётся в пикселях retina (обычно ×3) и часто ещё
масштабирован для показа — пересчёт почти всегда промахивается мимо нужного
элемента. Тот же временный XCUITest снимает `XCTAttachment(screenshot:)` для
итоговой визуальной приёмки — второй инструмент для этого не нужен.

Владелец 29.09.2026, после серии промахов мимо элементов на кадрах симулятора
в одной из сессий: «ты заебал, когда ты уже начнёшь это делать нормально».
