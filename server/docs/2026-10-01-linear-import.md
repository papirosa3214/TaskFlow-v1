# Linear → TaskFlow: первый этап

Согласованный результат: владелец открывает общую интеграцию, выбирает задачи Linear, проверяет полный состав переноса и подтверждает импорт. Задачи Linear становятся карточками TaskFlow, sub-issues — дочерними карточками через существующий parent_id. Шаги исполнения не создаются. Новые карточки не запускают агентов.

## Схема

Источник — общий аккаунт Composio владельца. Сервер выполняет только собственные фиксированные GraphQL queries; клиент не передаёт GraphQL и инструменты записи не используются. Списки, дочерние задачи, комментарии и связанные коллекции читаются с пагинацией и отказом вместо скрытого усечения.

Preview строит замкнутую иерархию выбранных задач: все потомки выбранных родителей и все необходимые предки; предки не тянут своих невыбранных соседних детей. Состав показан до записи. Снимок preview имеет срок и владельца; импорт использует именно подтверждённый снимок. Повтор импорта идемпотентен.

Модель TaskFlow сохраняется: title, markdown description, due_date, priority, status active/completed и parent_id. Исходные UUID, workspace, URL, статусы, исполнители, проекты, метки, связи, вложения и история хранятся в таблицах интеграции. Комментарии отображаются в обычной истории с явной подписью внешнего автора; внешние люди не превращаются во внутренних агентов. Недоступные вложения не имитируются локальными файлами.

Повторное обновление — трёхстороннее сравнение локального поля, ранее применённого значения и нового исходного значения. Локальные правки сохраняются; конфликт показан в preview. Удалений карточек и обратной записи нет. Источники и ранее применённые значения сохранены для будущего этапа обратной синхронизации.

Импорт одной подтверждённой структуры выполняется транзакцией. Связи-зависимости между импортированными карточками используют существующие task_dependencies с проверкой циклов; остальные связи сохраняются с исходным типом и ссылками в метаданных. При ошибке полноты/целостности записи не начинается. Проект назначения выбирается явно; назначение роли и исполнителя оставлено владельцу.

## Проверка

TypeScript build PASS. Полный серверный набор: 793 теста в 107 файлах PASS. 28 тематических проверок Linear/Composio: иерархия, пагинация, авторизация, фоновые задания, идемпотентность, локальные правки, документы, восстановление явно повторно выбранной удалённой карточки и транзакционный откат. Полный прогон включает чужие role-home изменения рабочей копии, которые этот коммит не включает.

iOS: 5 XCTest + 1 временный XCUITest PASS; итоговая сборка/5 XCTest PASS после удаления демонстрационных маршрутов. Кадры: /Users/max/Проекты/TaskFlowNativeBuild/docs/2026-10-01-linear-import.md.

Живая read-only проверка Composio: активных Linear-аккаунтов у владельцев нет. Реальный GraphQL снимок аккаунта не проверен. Без deploy на .110 и без переноса живых карточек. TaskFlow MCP docs вернул 401; артефакт сохранён локально.

## API и пределы

- GET /api/integrations/linear/issues?cursor=… — страницы по 50 карточек, включая архив.
- POST /api/integrations/linear/preview — issue_ids (1–50 UUID), project_id; async:true возвращает 202/job_id. Синхронный режим остаётся для CLI.
- GET /api/integrations/linear/previews/:job_id — loading/ready/failed, просмотр; только владелец. До двух загрузок одновременно; задания исчезают при перезапуске.
- POST /api/integrations/linear/import — только preview_id; клиентские поля карточек игнорируются.

До 500 карточек, 5000 элементов/100 страниц коллекции, 20 МБ снимка и 10 минут подготовки. Превышение останавливает подготовку явно. Просмотр действует 15 минут. Миграция 085 создаёт отдельные таблицы.

Composio LINEAR_RUN_QUERY_OR_MUTATION: версия 20260924_00, аргумент query_or_mutation. Только фиксированные queries сервера, общий owner userId и единственный ACTIVE connectedAccountId. GraphQL errors, даже при HTTP 200, останавливают чтение; отсутствие или неоднозначность аккаунта отвергаются.

## Границы первого этапа

Вложения — ссылки, документы — комментарии с авторством. История сохраняется текстом исходных изменений. Отменённый статус остаётся active с предупреждением. Название/цвет существующих меток остаются локальными; новые значения источника хранятся в метаданных. Внешний исполнитель не превращается во внутреннюю роль по имени. Активная внутренняя работа сохраняет статус/родителя. Обратной записи и удаления карточек нет.
