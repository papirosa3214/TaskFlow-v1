# Руководство: Подключение и настройка AI-агентов в TaskFlow (от А до Я)

Полная практическая инструкция по заведению, настройке ключей, подключению по MCP и автономной работе агентов (Claude Code, Antigravity, Hermes, DeepSeek, ChatGPT, Qwen и любых кастомных моделей) в TaskFlow.

---

## 🧭 Как устроена работа агентов в TaskFlow

В TaskFlow есть **два режима** взаимодействия с AI-ассистентами:

1. **Интерактивный / MCP-режим:**
   - Агент подключается через MCP-сервер (`server/scripts/mcp_server.py`) к вашей среде разработки (Claude Code, Antigravity IDE, Cursor, Windsurf и др.).
   - Вы общаетесь с агентом в диалоге, а он своими инструментами видит назначенные на него задачи, берёт их в работу, закрывает подзадачи, прикрепляет логи/скриншоты и сдаёт результат.
2. **Автономный режим («Будильник» / `trigger.py`):**
   - Вы включаете тумблер **«Будильник»** в Настройках приложения и назначаете задачу на агента.
   - Фоновая служба на сервере ловит назначение через WebSocket и сама поднимает фоновый процесс агента. Тот автономно выполняет задачу, продлевает 5-минутную аренду активности (`heartbeat`) и переводит карточку в статус «На проверке» (`review`).

## 1. Шаг 1: Заведение агента и получение API-ключа

### Способ А: Через интерфейс приложения (iPhone / Web)

1. Откройте TaskFlow → перейдите в **«Настройки»** ⚙️ → **«Команда»** (или вкладку «Команда» в боковом меню).
2. В блоке **«Новый агент»** нажмите **«+ Завести агента»**.
3. Введите имя (например: `Antigravity`, `GPT-5`, `DevBot`).
4. Нажмите **«Завести агента»**.
5. Сервер сгенерирует и покажет персональный ключ доступа:
   ```
   tf_e0d4ae5529f272a989c85bad13208b5a4288a273bc760b046f226b580ebe0c38
   ```
   > ⚠️ **ВАЖНО:** Ключ показывается **ровно один раз** в момент создания (в целях безопасности в базе хранится только его криптографический отпечаток). Скопируйте и сохраните его.

### Способ Б: Через REST API (из терминала)

```bash
TOKEN=$(curl -sS -X POST http://192.168.1.110:3001/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"maksim@test.com","password":"<ваш_пароль>"}' | jq -r .token)

curl -sS -X POST http://192.168.1.110:3001/api/agents \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"name":"Новый_Агент"}'
```

## 2. Шаг 2: Установка нативной аватарки для агента

У каждого агента в TaskFlow может быть собственная нативная аватарка без фона (PNG с прозрачным альфа-каналом):

1. Подготовьте квадратное изображение PNG (512×512) с прозрачным фоном.
2. Сохраните файл на сервере в `/home/maksim/Проекты/New-Todoist/server/uploads/avatars/<uuid>.png`.
3. Привяжите аватарку к агенту в SQLite базе данных:

```bash
sqlite3 /home/maksim/Проекты/New-Todoist/server/taskflow.db \
  "UPDATE users SET avatar_url = '/api/avatars/<uuid>.png' WHERE name = 'Имя_Агента';"
```

Картинка сразу появится в карточках задач, на доске и в Dynamic Island на iPhone.

## 3. Шаг 3: Подключение агента через MCP (Model Context Protocol)

TaskFlow поставляется с готовым MCP-сервером `server/scripts/mcp_server.py`, реализующим протокол JSON-RPC по `stdio`.

### 3.1. Подключение в Antigravity / Gemini IDE

В файле `~/.gemini/config/mcp_config.json` (или `.agents/mcp_config.json`):

```json
{
  "mcpServers": {
    "taskflow": {
      "command": "python3",
      "args": ["/Users/max/Projects/TaskFlow/server/scripts/mcp_server.py"],
      "env": {
        "TASKFLOW_API": "http://192.168.1.110:3001",
        "TASKFLOW_TOKEN": "tf_ваш_токен_агента"
      }
    }
  }
}
```

### 3.2. Подключение в Claude Code

В глобальном конфиге `~/.claude.json`:

```json
{
  "mcpServers": {
    "taskflow": {
      "command": "python3",
      "args": ["/home/maksim/Проекты/New-Todoist/server/scripts/mcp_server.py"],
      "env": {
        "TASKFLOW_API": "http://localhost:3001",
        "TASKFLOW_TOKEN": "tf_ваш_токен_агента"
      }
    }
  }
}
```

Или через команду:

```bash
claude mcp add taskflow python3 /home/maksim/Проекты/New-Todoist/server/scripts/mcp_server.py
```

### 3.3. Подключение в Cursor / Windsurf / VS Code

В настройках MCP (`settings.json` или вкладка MCP):

- **Name:** `TaskFlow`
- **Command:** `python3`
- **Args:** `/path/to/TaskFlow/server/scripts/mcp_server.py`
- **Env:**
  - `TASKFLOW_API`: `http://192.168.1.110:3001`
  - `TASKFLOW_TOKEN`: `tf_ваш_токен_агента`

## 4. Шаг 4: Настройка автономного запуска по Будильнику (`trigger.py`)

Если вы хотите, чтобы при включении тумблера **«Будильник»** на телефоне агент автоматически просыпался и шёл делать задачу:

1. Откройте файл `server/scripts/trigger.py`.
2. В словаре `EXTERNAL_AGENTS` зарегистрируйте ID пользователя агента и команду его вызова:

```python
EXTERNAL_AGENTS = {
    # ID пользователя в базе TaskFlow
    "5b9d47c1-25c7-4a7c-a276-70e21f7d7816": {
        "name": "Antigravity",
        "token_env": "TASKFLOW_ANTIGRAVITY_TOKEN",
        "token_static": "tf_e0d4ae5529f272a989c85bad13208b5a4288a273bc760b046f226b580ebe0c38",
        "cmd": ["agy", "run", "--prompt"],   # Команда вызова CLI агента
        "model_flag": "--model",             # Флаг подстановки модели из меток
    },
}
```

3. Служба `taskflow-trigger.service` автоматически подключится отдельным WebSocket-потоком под учёткой этого агента и будет слушать назначения.

## 5. Шаг 5: Полный жизненный цикл задачи агента

### Как правильно работать с агентом:

1. **Создание и назначение:**
   - В приложении создайте задачу с подзадачами (шагами).
   - Назначьте ответственным нужного агента (например, `Antigravity`).
   - _(Опционально)_ Повесьте метку модели: `Sonnet`, `Opus`, `Haiku` или `модель:gemini-1.5-pro`.

2. **Взятие в работу:**
   - Агент вызывает `taskflow_claim(id="...")`.
   - Карточка переходит в статус **«В работе»** (`in_progress`), на iPhone в Dynamic Island появляется плашка задачи.
   - Стартует **5-минутная аренда**. Пока агент работает, он вызывает `taskflow_heartbeat()`. Если агент упал и 5 минут молчит, система помечает карточку статусом «Агент пропал» (не врёт владельцу).

3. **Выполнение подзадач:**
   - Агент переводит текущий шаг в работу: `taskflow_subtask_work(id="...", state="in_progress")`. На телефоне у этой подзадачи начинает вращаться спиннер 🔄, а в Dynamic Island отображается название текущего шага!
   - Завершив шаг, агент вызывает `taskflow_subtask_done(id="...", done=true, result="Что именно сделано")`.

4. **Сдача на проверку:**
   - Завершив все шаги, агент вызывает `taskflow_state(id="...", state="review", comment="Работа завершена, вот детали...")`.
   - Ответственным **автоматически становится Владелец** (Максим), на телефон приходит уведомление о сдаче задачи.

5. **Если возник затык / нужен ответ:**
   - Агент вызывает `taskflow_state(id="...", state="blocked", comment="Не хватает прав/ключа...")`.
   - Задача становится красной, статус переключается на «Заблокирована», ответственным становится владелец.

## 6. Справочник инструментов MCP TaskFlow

| Инструмент                     | Назначение                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| `taskflow_my_tasks`            | Список задач, назначенных на текущего агента (`state: free, in_progress, review, blocked`) |
| `taskflow_task`                | Полная карточка задачи: описание, подзадачи, история ленты и комментарии                   |
| `taskflow_claim`               | Взять задачу в работу (`in_progress`) и открыть 5-минутную аренду                          |
| `taskflow_heartbeat`           | Продлить аренду задачи («пульс активности»)                                                |
| `taskflow_subtask_work`        | Переключить статус конкретного шага (`in_progress` / `blocked` / `null`)                   |
| `taskflow_subtask_done`        | Отметить шаг выполненным с обязательным отчётом `result`                                   |
| `taskflow_subtask_add`         | Добавить новый шаг в задачу (в конец или после `after_id`)                                 |
| `taskflow_state`               | Сменить статус задачи (`review` — сдать, `blocked` — затык, `in_progress` — возобновить)   |
| `taskflow_comment`             | Отправить комментарий в ленту и прикрепить файлы/логи                                      |
| `taskflow_projects`            | Список проектов, их ID и есть ли у проекта папка документации                              |
| `taskflow_project_tasks`       | Все задачи проекта с сортировкой по срочности                                              |
| `taskflow_create_task`         | Создать новую задачу со списком подзадач                                                   |
| `taskflow_create_project`      | Завести проект (по умолчанию — сразу с папкой документации)                                |
| `taskflow_agents`              | Список всех участников команды и их онлайн-статус                                          |
| `taskflow_status`              | Сводка состояния системы: активные задачи, просроченная аренда, ожидания                   |
| `taskflow_rules`               | Правила учёта работы агента — их же присылает сервер в ответе на `claim`                   |
| `taskflow_suggest_subtasks`    | Умная разбивка на шаги — та же кнопка, что у владельца в форме задачи                      |
| `taskflow_structure_dictation` | Разговорный/надиктованный текст → чистые `title` / `description` / шаги                    |
| `taskflow_docs`                | Документация проекта: папка и список лежащих в ней заметок                                 |
| `taskflow_doc_read`            | Заметка целиком, в markdown                                                                |
| `taskflow_doc_write`           | Создать заметку в папке проекта или дополнить существующую                                 |

## 7. Документация проекта: как агент её читает и пишет

У проекта может быть **папка заметок** — это и есть его документация. Папка не отдельная
сущность: она живёт в Дневнике, видна владельцу на телефоне, перетаскивается как обычная, а
проект просто на неё ссылается (`projects.notes_folder_id`). Удалили папку — проект теряет
привязку, но сам цел.

**Откуда папка берётся:**

- агент завёл проект сам — `taskflow_create_project(name="…")` создаёт папку с тем же
  названием автоматически (отключается флагом `with_docs=false`);
- проект человека — владелец прикрепляет папку на экране проекта.

**Как работать:**

```
taskflow_docs(project="Название")        → папка + список заметок с id и началом текста
taskflow_doc_read(id="…")                → полный текст заметки в markdown
taskflow_doc_write(project="…", markdown="# Заголовок\n\nТекст")   → новая заметка
taskflow_doc_write(id="…", markdown="…")                          → дописать в конец
taskflow_doc_write(id="…", markdown="…", mode="replace")          → переписать целиком
```

Названия заметки отдельным полем нет — им становится **первая строка** текста. У проекта без
папки инструменты не падают, а отвечают «папка не заведена» и подсказывают, как её завести.

**Что нужно знать про markdown.** Заметки хранятся деревом редактора (TipTap), а агент
говорит на markdown — сервер переводит в обе стороны (`server/src/lib/markdownToTiptap.ts` и
`tiptapToMarkdown.ts`). Переживают круг без потерь: заголовки, абзацы, списки любой
вложенности, нумерованные списки, чек-боксы `- [ ]` / `- [x]`, цитаты, блоки кода,
горизонтальная черта, `**жирный**`, `*курсив*`, `` `код` ``, `==выделение==`, ссылки. Две
оговорки:

- **таблиц редактор не умеет** — строки таблицы лягут отдельными абзацами, текст не
  потеряется, но разметка пропадёт. Табличные данные лучше давать списком;
- при чтении точки, скобки и дефисы приходят экранированными (`итог\.`) — так и задумано,
  при записи обратно экранирование снимается. Читать текст это не мешает.

**Зачем это агенту.** Итог работы кладётся не только в комментарий задачи (он утонет в
ленте), а в документацию проекта — туда, где владелец и следующий агент найдут его через
месяц. Перед началом работы по проекту стоит заглянуть в `taskflow_docs`: возможно, разбор
уже написан.
