# Ветки и рабочие копии

Этот документ — единственный источник правил по веткам. Его цель — не дать
потерять iOS-изменения или случайно начать работу не в той линии разработки.

## Активная ветка iOS: `native-app`

Все текущие изменения нативного приложения iOS, Capacitor-моста и связанных
веб-экранов делаются в **`native-app`**. Не начинать такую работу в `main`.

- Каноническая рабочая копия: сервер `.110`,
  `/home/maksim/Проекты/New-Todoist`, ветка `native-app`.
- Общий Git-remote: `ssh://git@192.168.1.110:2222/maksim/New-Todoist.git`
  (`origin`; веб-интерфейс Gitea: `https://git.mizernyukmy.netcraze.pro/maksim/New-Todoist`).
- `main` остаётся стабильной основной линией. Не вливать из неё в
  `native-app` и не переключать рабочую копию без отдельной задачи на
  синхронизацию.

## Перед началом работы

В каждой копии сначала проверить контекст:

```bash
git branch --show-current
git status --short --branch
git log -1 --oneline
```

Для работы с iOS ответ первой команды должен быть `native-app`. Если ветка
на сервере опережает `origin/native-app`, она ещё не опубликована: не делать
`reset`, `rebase` или `pull`, пока не проверен её журнал и не согласован
порядок публикации.

## Синхронизация и публикация

1. Коммитить завершённый логический кусок в `native-app`.
2. Перед `push` ещё раз выполнить `git status --short --branch`.
3. Публиковать только явной командой `git push origin native-app`.
4. При необходимости влить работу в `main` — сделать отдельный review/PR;
   это не часть обычной iOS-сборки.

Не копировать поверх работающей директории другой клон и не удалять чужие
незакоммиченные файлы. Для отдельной работы создать новую копию из
`native-app`.
