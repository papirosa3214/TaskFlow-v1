# Серверный конвейер глубокого исследования — дизайн

Дата: 21.09.2026. Проект: `New-Todoist` (сервер + веб). Повод — остаток работ
по роли-исследователю: порядок «план → сбор →
проверка → синтез → отчёт» жил только в промпте роли
(`server/scripts/role-prompts/researcher.md`), то есть держался на дисциплине
модели. Владелец просил «зафиксировать конвейер на сервере».

## Решения владельца (21.09.2026)

1. **Включение** — отдельное поле задачи `needs_research` + галочка в карточке,
   видна в списке. Ставит владелец или Секретарь при постановке.
2. **Модели** — раздельно: план и проверка облачной моделью роли (**MiniMax-M3**),
   синтез отчёта — локальной Ollama (`qwen3.6-27b`). Облачная берётся ровно та же,
   что у роли `researcher`, и тем же путём: имя из `role-routing.yaml`
   (`models.researcher`), запись модели из стора Pi, ключ из
   `~/.pi/agent/auth.json`, endpoint `api.minimax.io/anthropic` (anthropic-messages).
   При недоступности облачной — откат на локальную, имя модели пишется в ленту.
3. **Запуск** — вручную, эндпоинтом/кнопкой (owner-only). Автоматику по флагу
   прикручивать после E2E.

## Архитектура

- **Поле и миграция:** `tasks.needs_research INTEGER NOT NULL DEFAULT 0`
  (миграция `052_needs_research`, идемпотентная). PATCH/GET задачи —
  `routes/tasks.ts` (`ALLOWED_FIELDS`, нормализация bool→int).
- **Точка запуска:** `POST /api/tasks/:id/research` (`routes/research.ts`),
  только владелец. Гейты: задача помечена флагом, нет параллельного прогона.
  Роут поднимает детач-процесс и сразу отвечает (приём от `manual-run.ts`).
- **Токен процесса:** короткоживущий JWT владельца (2 часа, `app.jwt.sign`),
  уходит только через окружение. Конвейер ходит в API как владелец, поэтому
  не зависит от назначения задачи.
- **Сам конвейер:** `server/scripts/research_pipeline.py`.
  - Шаги: план (2–4 проверяемые части) → сбор (поиск + выкачка страниц чистым
    markdown + OCR вложений + поиск по базе знаний) → проверка достаточности и
    противоречий → синтез в markdown → `taskflow_report`.
  - Инструменты сбора переиспользуются из боевого `server/scripts/mcp_server.py`
    (тот же код, что у агента-исследователя).
  - Модели: план и проверка — облачная MiniMax-M3 (как у роли), синтез —
    локальная Ollama. Выход наружу — через xray `127.0.0.1:10811` (тот же выход,
    что прописан в профиле роли; `NO_PROXY` на localhost, чтобы запросы к самому
    TaskFlow не шли через прокси).
  - Потолки: `RESEARCH_MAX_ROUNDS=3`, `RESEARCH_MAX_SOURCES=10`,
    `RESEARCH_SOURCES_PER_QUERY=3`, `RESEARCH_SOURCE_CHARS=6000`. Останов: флаг
    «достаточно», потолок источников, отсутствие новых источников.
  - Статусы каждого шага — комментарием в ленту карточки + живой строкой
    активности; при сбое — понятная причина, а не тишина.
- **Итог:** `POST /api/tasks/:id/reports` — светлый HTML+PDF, зеркало-заметкой
  в доках проекта, отдельная секция «Отчёты» в карточке.

## Клиенты

- **Веб** (`src/`): поле в `types.ts`/`tasks.ts`, тумблер и кнопка запуска в
  `TaskDetailScreen.tsx`, бейдж «Исследование» в `TaskRow.tsx`.
- **iOS** (`TaskFlowNativeBuild`, scope `LOCK-191`): поле в `Task.swift`,
  `startResearch` в `APIClient+Tasks.swift`, пункты меню «…» в `TaskFormScreen`
  и `TaskFormViewModel`, бейдж в `DirectoryTaskRow`.
