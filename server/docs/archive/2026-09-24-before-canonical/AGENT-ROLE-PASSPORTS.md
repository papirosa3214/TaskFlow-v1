# Паспорт восьми ролей TaskFlow

> Уточнено 22.09.2026 по коду. Роли — ручные исполнители владельца: автоматической оркестрации нет, служба-будильник выключена и ни разу не запускалась. Исполняет их `pi_runtime` (бинарь `pi` с моделью), отдельной сущности «Pi-агент» не существует — это имя осталось в старых текстах.

Актуальная схема ролей, профилей, инструментов и навыков для проекта TaskFlow.

## Общая схема

- Все восемь ролей исполняются одним `pi_runtime` с моделью MiniMax-M3.
  Модель может меняться по **лесенке** (`model_ladder`): лимит учётки — вбок
  на соседнюю той же ступени, нехватка способностей — вверх. Таблица моделей — в `server/scripts/trigger.py`.
- Роль выбирается явным профилем при запуске:
  `pi --mcp-config ~/.pi/agent/taskflow-profiles/<role>.json`. Обычный `pi`
  без этого флага роли не получает. Запуск по карточке —
  `server/scripts/manual_run.sh --once <task-id>`.
- Автоматический будильник и старый контур вызова разных оболочек выключены.
- Старые учётные записи сохранены для истории, но новые запуски через них не маршрутизируются.
- Каждая роль имеет полный набор штатных инструментов TaskFlow: задачи, дочерние задачи, статусы, комментарии, проекты, документацию и поиск по базе знаний.
- Дополнительные внешние инструменты и навыки выдаются адресно, по роли; они не попадают в обычный разговор с `pi`.

## Общий результат работы

Каждая роль должна возвращать результат в едином формате:

```json
{
  "ok": true,
  "output": "содержательный результат",
  "artifacts": [],
  "error": null,
  "next_hint": "следующий шаг",
  "needs_human": false
}
```

Если требуется решение пользователя или внешнее действие, роль указывает это через `needs_human: true`, а не выполняет действие молча.

## Роли

| Роль | Идентификатор | Профиль | Назначение | Дополнительная специализация |
|---|---|---|---|---|
| Исследователь | `researcher` | `~/.pi/agent/taskflow-profiles/researcher.json` | Ищет источники, собирает факты и проверяет их | Интернет-поиск, извлечение источников, проверка цитат |
| Аналитик | `analyst` | `~/.pi/agent/taskflow-profiles/analyst.json` | Сравнивает данные, находит закономерности и риски | Табличный анализ, расчёты, структурирование данных |
| Синтезатор | `synthesizer` | `~/.pi/agent/taskflow-profiles/synthesizer.json` | Собирает выводы из нескольких материалов | Сводки, требования, decision brief |
| Критик-проверяющий | `critic_verifier` | `~/.pi/agent/taskflow-profiles/critic_verifier.json` | Ищет ошибки, противоречия и пропуски | Ревью, верификация, проверочные сценарии |
| Архитектор | `architect` | `~/.pi/agent/taskflow-profiles/architect.json` | Проектирует структуру решения и границы компонентов | Архитектурные решения, диаграммы, API-контракты |
| Разработчик | `builder` | `~/.pi/agent/taskflow-profiles/builder.json` | Реализует изменения в коде и конфигурации | Bash, Git, тесты, отладка |
| QA | `qa` | `~/.pi/agent/taskflow-profiles/qa.json` | Проверяет готовый результат и регрессии | Тест-планы, воспроизведение ошибок, отчёты о качестве |
| Дизайнер интерфейсов | `designer` | `~/.pi/agent/taskflow-profiles/designer.json` | Проектирует веб- и мобильный интерфейс | Визуальная система, UX, accessibility, frontend design |

## Общие инструменты TaskFlow

Этот набор есть у каждой роли:

`taskflow_my_tasks`, `taskflow_task`, `taskflow_claim`, `taskflow_heartbeat`, `taskflow_state`, `taskflow_comment`, `taskflow_subtask_done`, `taskflow_subtask_add`, `taskflow_rules`, `taskflow_status`, `taskflow_agents`, `taskflow_chat_send`, `taskflow_chat_typing`, `taskflow_chat_read`, `taskflow_subtask_work`, `taskflow_projects`, `taskflow_project_tasks`, `taskflow_create_project`, `taskflow_create_task`, `taskflow_suggest_subtasks`, `taskflow_structure_dictation`, `taskflow_docs`, `taskflow_doc_read`, `taskflow_doc_write`, `taskflow_kb_search`.

Это означает, что любая роль может взять задачу, вести статус, оставлять комментарии, создавать дочерние задачи и записывать итог в проектную документацию.

## Внешние инструменты по ролям

Внешние инструменты не являются частью общего TaskFlow-набора и подключаются только в профиль роли.

| Роль | Что разрешено подключать | Что не делается автоматически |
|---|---|---|
| Исследователь | Веб-поиск, чтение страниц, извлечение источников | Публикация или отправка наружу без человека |
| Аналитик | Bash для расчётов, таблицы, локальные скрипты | Изменение внешних систем без подтверждения |
| Синтезатор | Чтение документов, поиск по базе знаний, локальная обработка текста | Самостоятельное принятие продуктового решения |
| Критик-проверяющий | Bash, тестовые команды, проверка diff и логов | Исправление чужого кода без отдельной задачи |
| Архитектор | Диаграммы, чтение репозитория, анализ API и зависимостей | Изменение архитектуры без зафиксированного решения |
| Разработчик | Bash, Git, тесты, отладка, создание дочерних агентов | Публикация или разрушительные операции без подтверждения |
| QA | Bash, тестовый раннер, логи, сценарии воспроизведения | Подмена результатов тестов или обход проверок |
| Дизайнер интерфейсов | Навыки frontend design и mobile design; в перспективе Figma, Playwright, Storybook | Изменение продакшен-интерфейса без задачи и проверки |

## Навыки

У дизайнера уже подключены адресные навыки:

- `~/.pi/agent/taskflow-role-skills/designer/frontend-design`
- `~/.pi/agent/taskflow-role-skills/designer/mobile-design`

Они загружаются только при запуске профиля `designer` и не меняют обычный профиль Pi-агента. Остальные роли используют штатные возможности Pi и TaskFlow; дополнительные навыки для них можно добавлять отдельными пакетами без изменения общего контура.

## Где это настроено

- Профили Pi: `~/.pi/agent/taskflow-profiles/*.json`.
- Маршрутизация ролей: `server/scripts/role-routing.yaml`.
- Тексты ролей: `server/scripts/role-prompts/*.md`.
- Подключение адресных навыков: `server/scripts/trigger.py`.
- Роль дизайнера: `server/scripts/role-accounts.yaml`, `server/scripts/role-prompts/designer.md` и профиль `designer.json`.
- Автоматический будильник: выключен.
