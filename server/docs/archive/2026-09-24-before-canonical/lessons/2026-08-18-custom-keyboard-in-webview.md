# Своя экранная клавиатура в Capacitor/WKWebView: что реально работает

Урок по работе 18.08.2026 над TaskFlow (iOS 26.6, iPhone Air, Capacitor 8.5,
React + Vite). Задача: заменить системную клавиатуру своей во всех полях
приложения. Всё ниже — проверено на живом устройстве или автотестом, не взято
из статей.

---

## 1. Главный вопрос: чем подавлять системную клавиатуру

Разведка по блогам 2020-2021 годов утверждала, что `inputmode="none"` в WebKit
не работает, и предлагала `readonly` (который гасит клавиатуру, но лишает поле
каретки — WebKit её в readonly не рисует).

**Измерение опровергло разведку.** На iOS 26.6:

| Поле                          | Инсет visualViewport | Системная клавиатура |
| ----------------------------- | -------------------- | -------------------- |
| с `inputMode="none"`          | **0 px**             | не всплыла           |
| контрольное, без атрибута     | **413 px**           | всплыла              |

Каретка при этом на месте, поле остаётся редактируемым.

**Вывод:** используем `inputmode="none"`. `readonly`, своя нарисованная каретка,
swizzling `inputView` и прочие обходы не нужны.

### Как измерить это самому, не глядя на экран

Ключ: WebKit **не** реализует `interactive-widget=resizes-content`, но
`window.visualViewport` при появлении клавиатуры обновляет исправно. Значит
факт всплытия измеряется программно:

```js
function probeKeyboard(label) {
  const vv = window.visualViewport;
  const before = vv.height;
  setTimeout(() => {
    const inset = Math.round(before - vv.height);
    console.error(`${label}: инсет ${inset}px → ${inset > 80 ? "ВСПЛЫЛА" : "нет"}`);
  }, 800);
}
```

Две вещи, без которых замер врёт:

- **пауза 800 мс** — клавиатура выезжает с анимацией 250-400 мс;
- **контрольное поле** без атрибута рядом. Без него «инсет 0» неотличимо от
  «прибор не мерит». Именно контроль дал 413 px и подтвердил измеритель.

Логи с устройства снимаются так:

```
xcrun devicectl device process launch --device <UDID> --console \
  --terminate-existing <bundle-id> > console.log 2>&1 &
```

`console.error` из JS попадает в этот лог (Capacitor проксирует консоль
WebView в нативный лог с префиксом ⚡️). Телефон должен быть **разблокирован** —
на заблокированном `devicectl` не запустит приложение и перехват не прицепится.

## 2. Подключать поля по одному — тупик

Первый заход ставил хук в общий компонент `TextField` и в четыре `textarea`.
На телефоне это провалилось сразу, по двум независимым причинам.

### 2.1. В проекте полно полей мимо общего компонента

`grep` нашёл 14 «сырых» `<input>`/`<textarea>`, написанных напрямую:
комментарий в задаче, названия проектов и меток, поиск, имя агента. На них
всплывала системная клавиатура. Подключение поимённо гарантированно забудет
следующее добавленное поле.

### 2.2. Гонка на нестабильной ссылке контекста

Даже там, где хук стоял, клавиатура не появлялась. Причина:

```tsx
// ПЛОХО: новый объект на каждом рендере провайдера
<KeyboardContext.Provider value={{ sync, activate, deactivate, forget, activeId }}>
```

```tsx
// в поле
useEffect(() => () => ctx.forget(id), [ctx, enabled, id]);
```

Фокус → `activate` → провайдер рендерится → **новый объект** `ctx` → эффект в
поле перезапускается → его cleanup зовёт `forget(id)` → активное поле
сбрасывается в том же кадре. Панель не появлялась вовсе.

Мемоизация значения контекста это бы починила, но правильный вывод другой:
**регистрация полей вообще не нужна.**

### Решение: делегирование по DOM

Провайдер:

1. проставляет `inputmode="none"` всем текстовым полям упреждающим обходом
   `document.querySelectorAll("input, textarea")`;
2. следит за новыми полями через `MutationObserver` (поля появляются в
   модалках и списках);
3. ловит `focusin`/`focusout` на `document`.

Никаких хуков в полях, никаких правок в 14 файлах, новые поля покрываются
автоматически. Опт-аут — атрибутом `data-system-keyboard` на поле или любом
родителе (работает и для сырых полей); поля с `type` из списка
`password/email/number/tel/date/...` пропускаются по типу.

**Атрибут обязан стоять ДО фокуса.** Если выставлять его в обработчике
`focus`, системная клавиатура успевает начать выезжать. Отсюда упреждающий
обход, а не установка по событию.

## 3. Четыре грабли, которые ловятся только на живом вводе

### 3.1. Тап по клавише закрывает панель

Клавиши `react-simple-keyboard` — настоящие `<button>` (и это правильно, совет
мейнтейнера по iOS-issue #2739). Тап по кнопке физически снимает фокус с поля →
`focusout` → панель закрывается на первом же символе.

`preventMouseDownDefault` у библиотеки на iOS этого **не** удерживает.

Через `e.relatedTarget` тоже не решается: на iOS при тапе по кнопке он
приходит `null`, и «ушёл на клавишу» не отличить от «ушёл вообще».

Рабочий способ — флаг, выставляемый в фазе **capture**, до того как фокус
уйдёт:

```js
document.addEventListener("pointerdown", onPointerDown, true);
document.addEventListener("touchstart", onPointerDown, true);
// onPointerDown: touchingKeyboard = target.closest("[data-app-keyboard]") !== null

// в focusout:
if (touchingKeyboard) {
  setTimeout(() => field.focus({ preventScroll: true }), 0);  // синхронно WebKit снова снимет
  return;
}
```

Плюс отложенное закрытие (~180 мс), чтобы переход фокуса между двумя полями не
мигал панелью.

### 3.2. Фокус, полученный до подписки на события

React выполняет эффекты **потомков раньше** эффектов родителя. Экран поиска
фокусирует своё поле через `autoFocus`, то есть до того, как провайдер-родитель
навесил слушатели. Тот `focusin` теряется, и панель не появляется — при том что
поле в фокусе и `inputmode="none"` стоит.

Лечится двумя добавками:

```js
// 1. при монтировании смотреть текущее состояние, а не только события
if (isOurField(document.activeElement)) activate(document.activeElement);

// 2. повторный тап по УЖЕ сфокусированному полю нового focusin не даёт
if (isOurField(target) && document.activeElement === target) activate(target);
```

### 3.3. MutationObserver на весь документ убивает удержание клавиши

Симптом от владельца: «зажимаю кнопочку, оно всё удаляет, потом лагает и
умирает», плюс «каретка себя нестабильно ведёт».

Причина — в наблюдателе за DOM, а не в клавиатуре. Библиотека при удержании
рекурсивно повторяет нажатие по таймеру (`handleButtonHold`). Каждое повторение
перерисовывает экран, каждая перерисовка даёт пачку мутаций, и на **каждую**
мутацию шёл полный `document.querySelectorAll("input, textarea")`. Десятки
полных обходов дерева в секунду поверх перерисовки списка задач.

Два правила:

```js
// 1. Не писать атрибут, если он уже такой: setAttribute с тем же значением
//    всё равно порождает мутацию → новый вызов наблюдателя → лишний круг.
if (isOurField(el) && el.getAttribute("inputmode") !== "none") {
  el.setAttribute("inputmode", "none");
}

// 2. Полный обход — ОДИН раз при монтировании. Дальше только добавленные узлы.
const observer = new MutationObserver((records) => {
  for (const record of records) {
    if (record.type === "attributes" && record.target instanceof Element) {
      mark(record.target);
      continue;
    }
    record.addedNodes.forEach((n) => { if (n instanceof Element) prepare(n); });
  }
});
```

**Как это тестировать.** Обычные клики Playwright удержание не воспроизводят —
нужен именно зажим:

```js
await page.mouse.move(cx, cy);
await page.mouse.down();
await page.waitForTimeout(1500);
await page.mouse.up();
```

Проверять после этого три вещи: символов стало меньше, панель жива, и
**следующий одиночный клик доходит** (если поток подвесил страницу, он не
дойдёт). Плюс каретку — `document.activeElement === поле` и
`selectionStart === value.length`.

### 3.4. Контент не поднимается над своей клавиатурой

Следствие успеха из §1: раз системная клавиатура не всплывает,
`visualViewport` **не сжимается** — значит вся существующая логика подъёма
форм (`--kb-inset` из `visualViewport`) про нашу панель ничего не знает, и
поля уезжают под неё.

Решение: панель замеряет свою фактическую высоту и публикует её, а вычислитель
инсета берёт максимум из двух источников:

```js
const inset = Math.max(vvInset, ownKeyboardHeight);
```

Важно, что **писатель CSS-переменной остаётся один** — иначе два источника
перебивают друг друга на каждом событии `scroll`. Панель сообщает о себе
собственным событием (`app-keyboard-resize`): ни `resize`, ни `scroll` при её
появлении не стреляют.

Замер именно `offsetHeight` через `ResizeObserver`, а не расчёт из CSS: высота
зависит от `safe-area-inset-bottom` и от строк, которые появляются и исчезают.

## 4. Ввод текста без правки существующих полей

Клавиатуре нужно писать в поле, у которого свой React-`onChange`. Синтетический
объект вида `{ target: { value } }` — хрупко (ломается на `currentTarget`,
`name`).

Рабочий приём: **нативный сеттер прототипа плюс bubbling-событие `input`.**

```js
function setNativeValue(el, next) {
  const proto = el instanceof HTMLTextAreaElement
    ? HTMLTextAreaElement.prototype
    : HTMLInputElement.prototype;
  Object.getOwnPropertyDescriptor(proto, "value").set.call(el, next);
  el.dispatchEvent(new Event("input", { bubbles: true }));
}
```

React слушает всплывающее `input`, а значение читает из своего дескриптора —
поэтому простое `el.value = next` он не заметит и вернёт старое при следующем
рендере. С этим приёмом существующие `onChange` работают как с живого ввода, и
интерфейсы компонентов менять не пришлось ни в одном файле.

Текст при этом считается **от `value`, переданного панели**, а внутренний буфер
библиотеки не используется вовсе (нет ни `onChange`, ни `input` у `<Keyboard>`).
Два источника правды, синхронизируемые через `setInput`, — это ровно то место,
где возникает рассинхрон при изменении значения извне (диктовка, очистка формы).

## 5. Автотест вместо человека

Обе поломки из §2 были найдены вручную на телефоне, хотя **ни одна не
специфична для iOS** — и гонка контекста, и потеря фокуса по тапу
воспроизводятся в обычном Chrome. Это была ошибка процесса: человек
использовался как тестовый стенд.

Харнесс — `scripts/kb-check.mjs`, `npm run check:keyboard`. Проверяет по
каждому полю: `inputmode=none` стоит → панель появилась по фокусу → символ дошёл
до поля → **панель не закрылась** → backspace работает. Плюс `{enter}` в
многострочном, подъём `--kb-inset`, закрытие по клику вне поля и отсутствие
своей клавиатуры на `/login`.

Три препятствия, каждое стоило захода:

1. **`vite preview` отдаёт HTTPS** (плагин `@vitejs/plugin-basic-ssl`
   действует и на preview). Страница по HTTPS + API по HTTP = смешанный
   контент, браузер режет. Заменено на свой статический сервер по HTTP с
   SPA-фолбэком (маршруты `/task/:id` на диске не существуют).
2. **CORS.** Сервер держит явный список источников. С произвольного порта
   preflight не отдаёт `access-control-allow-origin`, браузер режет запрос, а
   приложение рисует «Нет соединения с сервером» — при полностью живом API.
   Лечится тем, что харнесс слушает **уже разрешённый** порт (5180), а не
   правкой сервера.
3. **Проверка порта сокетом врёт.** `net.connect` по `127.0.0.1` возвращал
   «занято» на сервер, слушающий `::1`, и «свободно» на живой сервер. Проверять
   HTTP-ответом.

Тест самодостаточен: создаёт задачу через API, проверяет на ней поле
комментария и удаляет её за собой — не зависит от того, что лежит в данных.

**Что нашёл сам харнесс, а не человек:** пропущенный `focusin` при `autoFocus`
(§3.2) — то есть он оправдал себя на первом же запуске.

## 6. Чего в клавиатуре нет (осознанно)

- строки автодополнения над панелью;
- долгого нажатия для дополнительных символов (в русской раскладке iOS «ъ»
  вводится долгим нажатием на «ь» — у нас его нет);
- английской раскладки и переключения языков;
- буфера обмена (системного меню на поле нет);
- squircle-скругления клавиш: у Apple непрерывная кривая, у нас дуга
  окружности. CSS так не умеет; пути — свойство `corner-shape` или SVG-маска на
  каждую клавишу.

Перемещение каретки внутри строки не поддержано намеренно: вставка всегда в
конец, `setCaretPosition` библиотеки не используется.

## 7. Короткий чек-лист для повторения

1. Замерить `inputmode="none"` на целевой ОС **с контрольным полем**. Не верить
   блогам.
2. Перехват — делегированием по DOM, не хуками в полях. Атрибут ставить
   упреждающе, до фокуса.
3. Держать фокус в поле при тапе по клавише: флаг в фазе capture + возврат
   фокуса следующим тиком.
4. Учесть фокус, полученный до подписки (`autoFocus`, эффекты потомков раньше
   родителя) и повторный тап по уже сфокусированному полю.
5. Поднять контент самостоятельно: `visualViewport` о своей клавиатуре не
   знает. Один писатель переменной, максимум из источников.
6. Писать в поле нативным сеттером + событием `input`.
7. Наблюдателя за DOM держать инкрементальным: полный обход только при
   монтировании, дальше — добавленные узлы. Атрибут не перезаписывать тем же
   значением.
8. Автотест на «панель не закрылась при вводе», на поток нажатий и на
   УДЕРЖАНИЕ клавиши (мышью, не кликами) — до того, как отдавать человеку.
