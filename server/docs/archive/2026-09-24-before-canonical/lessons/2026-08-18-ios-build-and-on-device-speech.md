## 4. Диагностика на устройстве без разработчика рядом

Главный принцип, добытый дорого: **не использовать человека как измерительный
прибор.** Всё, что можно измерить самому, надо измерять самому.

### 4.1. Логи с устройства

```bash
xcrun devicectl device process launch --device <UDID> --console \
  --terminate-existing <bundle-id> > console.log 2>&1 &
```

- Телефон обязан быть **разблокирован**, иначе: `FBSOpenApplicationErrorDomain
  error 7 (Locked)` — приложение не запустится и перехват не прицепится.
- `console.error` из JS попадает сюда (префикс ⚡️) — при `loggingBehavior:
  production` в том числе в Release.
- Сессия `--console` может отцепиться, оставив приложение работать. Проверяй
  `pgrep -f "devicectl.*console"`.

### 4.2. Что можно делать самому, а что нельзя

Сам: установка, перезапуск приложения, чтение логов, замер времени, повторный
запуск для второго замера, прогон харнесса в Chrome.

Нельзя: тапать по экрану и видеть картинку. Значит от человека нужны только
действия руками — и просить их надо по одному, с конкретным вопросом.

### 4.3. Измерять, а не гадать

Три примера из этой сессии, где замер опроверг «известное»:

- **Подавление системной клавиатуры.** Блоги 2020-2021 утверждали, что
  `inputmode="none"` в WebKit не работает. Замер по `visualViewport`: инсет 0 px
  против 413 px у контрольного поля. Работает.
- **Причина зависания прогрева.** Текст ошибки таймаута утверждал, что виноват
  сетевой поход за токенизатором. Это была догадка, зашитая в сообщение;
  HuggingFace отвечал 200. Настоящая причина — §5.3.
- **Нагрев.** Замер холостого хода клавиатуры: 0 мутаций DOM, 0 срабатываний
  ResizeObserver за 5 с простоя. Значит искать надо было не там.

**Сообщение об ошибке не должно утверждать причину, которой не знает.** Только
факт: «не завершилось за N с и было прервано».

## 5. Распознавание речи на устройстве

Три независимых механизма, у каждого свои требования. Путать их — источник
половины потерянного времени.

### 5.1. Whisper через WhisperKit (основной путь)

Работает в любом регионе, Apple Intelligence не нужен.

- Пакет добавляется в **App.xcodeproj**, а не в `CapApp-SPM/Package.swift`: тот
  помечен «DO NOT MODIFY — managed by Capacitor CLI» и перезаписывается при
  `cap sync`. Добавлять удобно через gem `xcodeproj` (лежит в
  `~/.gem/ruby/2.6.0`, запускать `/usr/bin/ruby` с `GEM_HOME`).
- WhisperKit требует **iOS 16+** — deployment target проекта поднят с 15.0 до
  16.0, иначе SPM не резолвится.
- Модели из `argmaxinc/whisperkit-coreml` приходят **уже скомпилированными**
  (`AudioEncoder.mlmodelc`, `TextDecoder.mlmodelc` и прочие). Компилировать
  нечего.
- Имена вариантов содержат размер: `openai_whisper-small_216MB`,
  `openai_whisper-large-v3-v20240930_turbo_632MB`. `.en`-варианты — только
  английский, для русского бесполезны.
- Токенизатор лежит в ДРУГОМ репозитории. Без `tokenizerFolder` WhisperKit,
  не найдя его рядом с моделью, уходит за ним в сеть (`loadTokenizerIfNeeded`).
  Задавать `downloadBase` и `tokenizerFolder` тем же каталогом, куда качали.

### 5.2. Замеры прогрева (iPhone Air, Release, turbo 632 МБ)

| Прогрев | Время |
| --- | --- |
| Первый после скачивания | **203 с** |
| Перезапуск приложения без переустановки | **7 с** |
| **Первый запуск ПОСЛЕ ПЕРЕУСТАНОВКИ** | **309 с** |

iOS специализирует `.mlmodelc` под Neural Engine и кэширует результат
(`com.apple.e5rt.e5bundlecache`). Ключевое, что стоило трёх часов путаницы:
**переустановка приложения этот кэш обесценивает**, и специализация идёт заново.
Модель при этом не перекачивается — время уходит внутри `WhisperKit(config)`.

Практический вывод для разработки: **пока идёт отладка модели, не переставлять
приложение.** За сессию 18.08.2026 было больше сорока установок, и каждая
возвращала прогрев к трём-пяти минутам — из-за этого казалось, что модель
«вообще не работает», хотя она работала. Если правки нужны часто — держать
`small` (216 МБ), у него обе цифры кратно меньше, а на turbo переключаться, когда
установки закончились.

### 5.3. Ошибка, которую нельзя повторять

Стоял таймаут прогрева **180 с** — то есть он обрывал законную работу за 23
секунды до финиша. Прогрев начинался заново при каждой попытке и **никогда не
заканчивался**: замкнутый круг создавал таймаут, а не устройство. Владелец
резонно возражал, что Superwhisper поднимает модель крупнее мгновенно, — и был
прав, дело было не в железе.

Правила по итогу:

- лимит отсекает **аварию**, а не медленную нормальную работу: 600 с;
- `prewarm: false` — лишний проход компиляции и прогона удваивает ожидание;
- прогрев запускать **при входе в приложение** и сразу после скачивания/выбора
  модели, а не лениво в момент диктовки: ждать модель три минуты с микрофоном в
  руках никто не будет;
- на время ожидания отдавать запасной движок (§5.4), а не блокировать.

### 5.4. DictationTranscriber (Speech.framework, iOS 26) — запасной путь

Та же плоская диктовка, что под микрофоном системной клавиатуры; качество не
выше её. Работает в любом регионе.

Главное, что тут выяснилось: **старый `SFSpeechRecognizer` непригоден.** У него
нет способа ДОСТАВИТЬ ассет — он умеет только спросить
`supportsOnDeviceRecognition` и сдаться. И отдаёт `false` даже когда у
пользователя русская клавиатурная диктовка скачана и работает, потому что
инвентарь ассетов приложения **отдельный от системного**. Скачать свою копию
умеет только `AssetInventory` (iOS 26+):

```swift
if await AssetInventory.status(forModules: [transcriber]) != .installed {
  if let request = try await AssetInventory.assetInstallationRequest(supporting: [transcriber]) {
    try await request.downloadAndInstall()   // ОБЯЗАТЕЛЬНО с таймаутом
  }
}
try await AssetInventory.reserve(locale: locale)
```

`downloadAndInstall()` **без сети не бросает, а висит бесконечно** — UI замирал
молча. Таймаут обязателен.

Почему `DictationTranscriber`, а не `SpeechTranscriber`: первый работает на тех
же ассетах, что системная клавиатурная диктовка, второй тянет свою модель с
нуля.

### 5.5. FoundationModels (разбор на подзадачи) — в РФ недоступен

`SystemLanguageModel.default.availability` возвращает
`unavailable(appleIntelligenceNotEnabled)`. Смена региона устройства не помогает:
русского нет в `supportedLanguages`, на русском тексте будет
`unsupportedLanguageOrLocale`. Рабочим остаётся серверный путь (Ollama на .110).

Код оставлен как есть — включится сам, если язык появится.

## 6. Плагин Capacitor в таргете приложения

**Плагин, живущий в таргете App, надо регистрировать руками.** Автоподхват
работает для плагинов-пакетов. Без регистрации JS получает
`{"code":"UNIMPLEMENTED"}`, обёртка глушит это в `catch` и молча уходит на
сервер — то есть нативный путь выглядит работающим, но не вызывается ни разу.
Именно так и было полдня.

```swift
public class LocalAIBridgeViewController: CAPBridgeViewController {
  public override func capacitorDidLoad() {
    bridge?.registerPluginInstance(LocalAIPlugin())
  }
}
```

И подставить этот класс в `SceneDelegate` вместо `CAPBridgeViewController`.
`capacitorDidLoad()` — единственная точка, где `bridge` уже существует, а
webView ещё не начал грузить JS.

Проверка, что плагин виден: в логе должно быть `To Native -> LocalAI …`, а не
`UNIMPLEMENTED`.

## 7. Аудио: формат имеет значение

`MediaRecorder` в WKWebView по умолчанию выбирали как в браузере —
`audio/webm;codecs=opus`. **AVFoundation WebM не декодирует ни при каком
расширении** и отдаёт `kAudioFileUnsupportedFileTypeError` (OSStatus
`1954115647` = `'typ?'`). Локальное распознавание из-за этого молча падало на
сервер.

Правила:

- на нативном iOS писать `audio/mp4`; серверному ASR формат безразличен (ffmpeg
  определяет сам), так что приоритет ничего не ломает;
- расширение временного файла брать из **реального MIME** записи, а не угадывать:
  AVFoundation определяет контейнер именно по нему;
- формат записи почти никогда не совпадает с тем, что хочет распознаватель —
  конвертировать через `AVAudioConverter`, иначе `analyzeSequence` бросает.

Расшифровка OSStatus: четырёхбайтовый код читается как ASCII. `1954115647` →
`0x7479703F` → `typ?`.

## 8. Разбор диктовки (даты, проекты, приоритеты)

Парсер — чистая функция `src/lib/dictationParser.ts`, regex, **без сети и без
модели**. Тестируется без телефона: `npx vitest run src/lib/dictationParser.test.ts`.

Поддерживает: `сегодня`, `завтра`, `послезавтра`, `через N дней`,
`в понедельник` (предлог обязателен), `15 августа`, `15 авг`, год числом.

Работает **только на заголовке новой задачи**: в описании и подзадаче разбор
отключён намеренно, при редактировании существующей — тоже.

Три ловушки:

1. **`\b` не работает с кириллицей.** `\w` = `[A-Za-z0-9_]`, русские буквы в него
   не входят, поэтому `/\bзавтра\b/.test("на завтра")` — false. Нужен ручной
   lookaround по явному классу букв.
2. **Съедать «хвосты» маркера.** Слово «года» после числа и предлог перед датой
   («до 10 сентября») иначе остаются в заголовке.
3. **Момент вызова.** Разбор должен идти сразу после вставки надиктованного
   текста. Когда микрофон переехал внутрь своей клавиатуры, прежний путь
   перестал вызываться, разбор остался на `onBlur` — и при быстром нажатии
   «Сохранить» срок не попадал в задачу. Решение: клавиатура бросает событие,
   форма слушает, вызов отложен на тик (иначе читается ещё не применённое
   React-ом значение).

Отображение: год в подписи срока показывать, **когда он не текущий**. «4 сен.»
для задачи на 2027 читается как «через две недели».

## 9. Что показывать пользователю

Выводы из живых претензий владельца, каждая — цитата:

- «Диктовка Apple. Модель не скачана» при скачанной модели — **подпись не должна
  утверждать причину, которую не проверяла.** Различать: не скачана / грузится N
  секунд / не загрузилась / прогрев не запущен.
- «Загружается — куда она загружается?» — **не путать скачивание из сети с
  подъёмом в память.** Формулировать явно: «скачиваю из сети» против
  «прогревается в память (сеть не нужна)».
- «Я модель удалил, а она пишет прогревается» — при удалении **отменять идущую
  загрузку** (`Task.cancel()`) и сбрасывать флаг; в UI проверять «не скачана»
  ПЕРЕД «прогревается».
- «Полоса прогресса пустая, а проценты идут» — цвет `bg-accent`, которого нет в
  теме проекта, не резолвится, и элемент рисуется прозрачным. Палитра:
  `bg/card/stroke/text/sub/dim/red/orange/pink/blue/purple/yellow/coral/teal/green`.
- «Плашка не исчезает» / «висит бесконечно» — у любого уведомления должен быть
  **отменяемый** таймер; новая диктовка не должна получать гашение от предыдущей.
- Статус лучше цветом: зелёный работает, жёлтый прогревается с секундами,
  красный не работает.

5. Плагин в таргете App **зарегистрирован** в `capacitorDidLoad()`.
6. Запись звука на iOS — `audio/mp4`, расширение из реального MIME.
7. Прогрев модели: запускать при входе, лимит 600 с, `prewarm: false`. Первая

8. Любой сетевой шаг с таймаутом — `downloadAndInstall()` и загрузка модели без
   него висят молча.
9. Сначала измерить самому (логи, харнесс, `vitest`), только потом просить
   человека тапнуть.
10. Ошибки и подписи — только факты, без версий о причинах.
