## 2026-09-27 04:20 — Урок об идемпотентности polling (баг + фикс)

Скилл `software-development/systematic-debugging` применил к багу в
`inboxResultsWriter.ts`: при перезапуске сервера каждая итерация
writer'a обрабатывала уже-обработанные tasks повторно → INSERT дочерней
card повторялся → 3 рестарта подряд = 1+3 = 4 копии.

Скилл прошёл 4 фазы:
1. tight loop воспроизводит баг (1 → 2 fix cards per restart)
2. pattern analysis: пример в `inboxTriageWatcher.ts` — файловые marker'ы
3. hypothesis: опираться на файловый marker + idempotent INSERT
4. implementation: SELECT INSERT, exception-fallback второй SELECT

Файлы:
- `server/src/lib/inboxResultsWriter.ts` — добавлен idempotent INSERT
- `~/kb/lessons/2026-09-27-polling-idempotency-restart.md` — урок залит в RAGFlow
- `docs/notifications/architecture.md` — обновлён раздел Конкурентность

Детерминированно проверено: 1 → 1 fix card после 3 рестартов подряд.
Скилл `systematic-debugging` сохранён в Mnemosyne как профилактический
чек-лист (см. запись в Mnemosyne от 27.09.2026).
