> Контракт: на стороне `.110` уже есть сервис, который читает уведомления.
> Эта страница — короткая выжимка. Полные детали — в
> [README.md](README.md), [api.md](api.md), [file-format.md](file-format.md),
> [lifecycle.md](lifecycle.md).

## Что есть на сервере (`192.168.1.110`)

HTTP API на **порту 5198**. Не требует авторизации (LAN).

```
GET /                              → справка
GET /notifications/inbox?date=YYYY-MM-DD     → список за день
GET /notifications/by-source?source=NAME&hours=N
GET /notifications/triage?date=YYYY-MM-DD    → только с тревогой
GET /notifications/raw?path=/abs/path.md     → полный markdown файла
```

Все запросы возвращают JSON. `Content-Type: application/json`.
Пример:

```json
{
  "id": "inbox/2026-09-27/015101-autonomy-110",
  "path": "/home/maksim/Проекты/taskflow-уведомления/inbox/2026-09-27/015101-autonomy-110.md",
  "title": "Автономность .110 — сводка за сутки",
  "ts": "2026-09-27T01:51:01",
  "source": "autonomy-110",
  "level": "error",
  "has_triage": true,
  "snippet": "Сводка уведомлений от 27.09.26\n...",
  "links": []
}
```

## Что показывать в iOS UI

### Экран Обзор → Уведомления (раздел)

Два подраздела (внутренний таб или секция):

1. **«Сторонние сервисы»** — НОВЫЙ (этот контур) — карточки-тикеты из
   inbox/.md файлов через API `notifications-api` (порт 5198).
2. **«Завершённые задачи»** — НЕ дёргает наш контур. Это просто ссылка
   на уже существующий экран TaskFlow «Закрытые задачи», который
   в приложении уже рисует свой собственный список закрытых задач.
   Подраздел «Завершённые задачи» в Уведомлениях = single nav-link «See
   completed tasks in TaskFlow». Никакого нового endpoint'а,
   никакого гибрида, никакого агрегатора. Это решение зафиксировано
   Maksim'ом 27.09.2026.

### Карточка-тикет в подразделе «Сторонние сервисы»

- Заголовок = `title` из JSON
- Под ним 4 поля: `ts`, `source`, `level`, `has_triage`
- Тело — содержимое блока `## Сводка (для отображения в приложении)` из `.md` файла
  (можно догрузить через `GET /notifications/raw` если snippet не хватает)
- Если `has_triage: true` — красная обводка + блок «Не отработали в штатном режиме» отдельно

### Состояние карточки

В `.md` файле может быть блок «Карточка диагностики» со ссылкой вида:
```
[карточка #88a18485](tf://task/88a18485-120a-4e97-ab20-e45a48d5fe58)
```

В iOS — клик открывает **соответствующую задачу в TaskFlow**. Никакого
контекстного меню, только ОТКРЫТЬ в нативном TaskFlow.

### Состояние «итога устранения»

В .md файле есть блок:
```
## Итог по устранению
- <problem> — (исправлено)
- <problem> — (не исправлено: ...)
```

Каждая строка:
- `(исправлено)` — неактивная серая (тап = открыть карточку)
- `(не исправлено: ...)` — активная красная (тап = модальный диалог)

### Модальный диалог

Поведение модалки:
```
[ показ строки-сноски как есть, с переносами строк ]

Кнопки:
  - "Выбрать один из вариантов"
    → если внутри строки есть 4 пункта (1/2/3 + «свой вариант»):
      открывает поле с 4 radio-button, дефолт = вариант 1
    → иначе: открывает просто текстовое поле (свободный ввод)
  - "Своё решение"
    → открывает поле textarea, пустое
    → submit = POST /api/tasks/<fix-id>/comments с введённым текстом
```

4 пронумерованных варианта пишутся writer'ом (backend-only), не
эмиттером и не исполнителем. Подробнее об источнике —
`file-format.md#откуда-берутся-3-подсказки`.

Submit (любой сценарий) →
`POST http://192.168.1.110:3001/api/tasks/<fix-id>/comments`
с `{"text": "<выбранный или введённый>"}`. TaskFlow автоматически
переводит карточку в работу.

## Webhook / события

Нет push — приложение **само опрашивает** GET /notifications/inbox раз
в N секунд. Или при WebSocket-событии от TaskFlow (`/api/ws`) — там
сервер уже шлёт уведомление о любом изменении.

Рекомендую: open WebSocket к TaskFlow `/api/ws`, слушай
`task_created`/`task_state_changed`/`task_commented` и обновляй кеш
уведомлений.

## Файлы как отладочный материал

После `GET /notifications/raw?path=...` приложение получает полный
markdown. В этом markdown:

- Блок `## Сводка (для отображения в приложении)` — то что показать
- Блок `## Сырые строки (для парсинга)` — для будущих фич (не парсить сейчас)
- Блок `## Карточка диагностики` — ссылка на созданную карточку
- Блок `## По результатам диагностики` — что выяснили
- Блок `## Итог по устранению` — финал

Все блоки кроме первого могут отсутствовать (пока не закрыта карточка).

## Чего НЕ делать в iOS

- ❌ Inline-кнопок (Telegram keyboard, HTML form, SwiftUI button-in-card)
- ❌ Свою submit-логику — используй стандартный TaskFlow `/api/tasks/:id/comments`
- ❌ Править текст .md файла — авторитет только за TaskFlow-сервером
- ❌ Слать свои уведомления в inbox/ — только через `alert_send` или `rendezvous`
- ❌ Менять формат сводки в коде — всё зафиксировано в [file-format.md](file-format.md)

## Что непонятно / вопросы

- Слать webhook в TaskFlow API при закрытии карточки — есть ли такой endpoint? Если нет, нужно polling `task_state_changed` через WS.
- Кто авторизует на 5198 — нужен ли bearer-токен для iOS? Сейчас сервис открыт, но в прод лучше ограничить.
