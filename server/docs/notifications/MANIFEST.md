> **Статус:** финальный после Phase 4. После следующих итераций — обновить.

> **Как пользоваться:** сравнить содержимое этого манифеста с тем, что

## Синхронизация

При каждом изменении на любой стороне:

1. Поправить файл на своей стороне (".110" или Mac).
2. Обновить запись в `history.md` (на `.110`, единый источник правды).
3. Скопировать изменённые файлы на вторую сторону.
4. На Маке запустить smoke-test: `https://192.168.1.110:5198/`.

**Источник правды для backend-документации — `.110`.** Mac не должен
создавать дублирующие .md без согласования с Maksim.

Mac может создавать дополнительные файлы (например, о SwiftUI-реализации,
дизайне модального окна и т.п.) — НО не дублирующие существующие.
Синхронизация не касается чисто-маковских docs (`*.ios.md`, дизайн).

## Что ЗАПРЕЩЕНО дублировать между сторонами

| Документ | Почему нельзя дублировать |
|---|---|
| README.md (notifications/) | Внутренняя точка входа, должна быть одна |

| lifecycle.md | Цикл реализован на одной стороне |
| operations.md | Серверные команды должны знать все |
| history.md | Журнал общий |

## Что если на Маке уже есть `2026-09-27-notifications-service-tickets-spec.md`

Эта спека появилась **до** того как сервер был поднят и контракт формализован.
В ней — живой curl на 5198. **Сравни с `integration-ios.md`** — содержимое
должно совпасть.

Дефолтное поведение — **вливать** спеку в `integration-ios.md` (тогда
`2026-09-27-...-spec.md` исчезает с Мака, остаётся единая правда в репо
TaskFlow). Или **заменить** `integration-ios.md` ссылкой на спеку.

Решение принимает Maksim — если Mac-разработчик сомневается, спросить.
