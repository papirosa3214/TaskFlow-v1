# Постоянные папки ролей TaskFlow

Согласовано с Максимом 01.10.2026: чат работает у роли, задача — в проекте; AGENTS.md, навыки и скрипты общие для обоих запусков и принадлежат роли.

## Размещение

По умолчанию `~/taskflow/roles/`. На .110 это `/home/maksim/taskflow/roles/`. Переопределение: `TASKFLOW_ROLES_DIR` в окружении серверного процесса.

```text
roles/
  builder/                      # Разработчик: постоянный ключ из roles.key
    AGENTS.md                   # постоянные инструкции роли
    skills/
      название-навыка/
        SKILL.md
        scripts/                # вспомогательные файлы самого навыка
    scripts/                    # инструменты роли и пользовательские скрипты
      mcp_server.py             # wrapper общего серверного протокола
    workspace/                  # рабочая папка чата, документы и результаты
    sessions/<идентификатор>/   # история Pi отдельно на каждый чат
    extensions/                 # расширения Pi для чата
    prompts/                    # шаблоны Pi для чата
  researcher/
    ...
    scripts/research_server.py  # wrapper исследовательских инструментов
```

Папки называются по ключам ролей (`builder`, `researcher`, `architect`, `analyst`, `critic_verifier`, `qa`, `designer`), а не по отображаемому названию. Переименование роли в интерфейсе не теряет её файлы. Новая роль получает тот же набор каталогов при первом запуске или bootstrap. Старые ключи с дефисом поддерживаются. Пути и произвольные названия вместо ключа запрещены.

## Что подключается

| Источник | Чат | Задача / подзадача / шаг плана |
| --- | --- | --- |
| Рабочая папка | `roles/<роль>/workspace` | проект карточки, для TaskFlow — существующая отдельная worktree |
| `AGENTS.md` | файл выбранной роли, с effective override | тот же файл и override |
| Файловые скиллы | только `roles/<роль>/skills` | тот же набор |
| Скрипты | абсолютные пути из папки роли | те же абсолютные пути; cwd проекта не меняется |
| Pi extensions и prompt templates | только папка выбранной роли | исполняемые расширения и шаблоны отключены, как в прежнем task runtime |
| Credentials, model routing, API permissions | управляет сервер | управляет сервер |

В контекст каждого запуска включаются абсолютные пути: куда создавать новый навык, куда класть общие скрипты и где лежат инструкции. Задача не создаёт навыки в своём проекте; чат не создаёт их в исходниках API. Это правило хранения в prompt, а не файловая sandbox: роль с инструментом bash по-прежнему имеет системные права пользователя сервера.

Глобальные ресурсы `~/.pi/agent` и ресурсы чужих ролей не подмешиваются автоматически. Старые файлы можно скопировать явно при миграции. Auth и настройки модели не копируются в папки ролей. Существующие DB-промпты ролей и API-настройки остаются действующими; AGENTS.md дополняет их, не создавая копию большого системного промпта.

Серверные Python-инструменты имеют wrappers у роли. Реализация протокола остаётся в исходниках сервера, чтобы обновления API не требовали рассинхроненных копий скрипта для каждой роли. Собственные скрипты роль создаёт рядом в своей папке.

## Продолжение существующих чатов

Pi восстанавливает cwd из заголовка JSONL, поэтому одной замены `RpcClient.cwd` недостаточно. При первом продолжении старого чата история с прежним ID копируется в `roles/<роль>/sessions/<hash chat ID>/`. Меняется только `cwd` в заголовке; остальные записи сохраняются без изменений. Оригинал остаётся в прежнем каталоге Pi. Следующие сообщения используют новую копию. Сброс сессии и история сообщений TaskFlow работают по прежним правилам.

## Подготовка каталогов и миграция

Запускать из каталога `server/` на нужной машине. Рекомендуется сначала dry-run:

```sh
npx tsx scripts/bootstrap-role-homes.ts --all --legacy-agent-dir "$HOME/.pi/agent" --dry-run
```

Проверить выбранные роли и пути. После разрешённой выкладки выполнить:

```sh
npx tsx scripts/bootstrap-role-homes.ts --all --legacy-agent-dir "$HOME/.pi/agent"
```

`--all` читает реестр ролей из БД в режиме read-only, не запускает миграции. Можно подготовить только одну роль: `--role researcher`, флаг повторяется для нескольких ролей. `DB_PATH` выбирает другую БД, `TASKFLOW_ROLES_DIR` — другой корень.

`--legacy-agent-dir` можно повторить для нескольких исходных каталогов. Импортируются только `skills`, `scripts`, `extensions`, `prompts` и AGENTS.md. Credentials и settings.json не импортируются. Для каждого источника прежний AGENTS.md добавляется один раз; другие файлы копируются только при отсутствии целого навыка/скрипта/расширения. Оригиналы не удаляются. При повторе локальные правки сохраняются. Общее наследие Pi копируется каждой выбранной роли для сохранения прежних возможностей; после этого новые и изменённые навыки принадлежат своей роли.

Не подключать произвольную старую папку, не проверив её содержимое: legacy extensions содержат исполняемый код. На .110 ранее обнаружены глобальные `taskflow-activity`, `taskflow-todo-mirror`, `verify-before-claim`, `orca-agent-status`, `subagent`; это не новые расширения данной реализации.

## Выкладка и откат

Код изменён в Mac checkout `/Users/max/Проекты/New-Todoist-server`. Живой сервер .110 запускается через `tsx watch`, поэтому pull может прервать текущие роли. Выкладка проводится отдельно, после решения владельца, согласно INDEX.md; активные чаты и задачи следует завершить до обновления.

При выкладке сначала сохранить прежний Git revision и резервную копию существующего `~/taskflow/roles` (если уже есть), затем обновить код, выполнить bootstrap и проверить реальный чат + запуск задачи. Истории и исходные глобальные файлы миграция не удаляет. Откат серверного revision возвращает прежний способ запуска; новую папку ролей сохранить с её результатами, а не удалять.
